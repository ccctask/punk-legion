# 黄铜转运场与线圈港攻防

适用于 M19 场次登记、攻守指挥、炮塔、结算和恢复。状态为生效，维护角色为世界地图、权威房间及档案服务负责人。验证版本为 Godot 4.6.1、SQLite 档案 v20。从本机签名内测 1011 的私人基地进入公共区域图。两地指挥台与战场共用各自的[资源地标布景](playable-art.md#黄铜转运场与线圈港)。黄铜转运场产结构材料，线圈港产通用零件，两处按各自服务端窗口实时争夺。1008 及之前的内测包需要覆盖升级。

## 进攻补给（签名内测 1041）

开发版的进攻补给按场计费。黄铜转运场和线圈港的指挥台显示首次开战所需的 1 份私仓能源和本人余额。查看、登记、预约免费；房间确认攻方入场并锁定编队时才扣这 1 份，无论胜负。余额不足时可回基地补足后再进攻，救援凭证不能代付。若预约后能源被另一项操作用掉，开战失败会回到指挥台刷新余额，机体仍可调度。已开场的攻方可在零余额时接回原场，指挥台显示原补给收据短号。守方接管与好友援军不承担这笔费用。

## 采集站（签名内测 1026）

占领营地后，从公开地图进入该地指挥台，点「建设采集站」查看报价。黄铜转运场消耗私人仓库 2 份结构材料，线圈港消耗 2 份通用零件。确认后，当前营地的产出从每 15 分钟一份加快到每 12 分钟一份。库存上限仍为八份，玩家需领取后才会腾出产能。建设前已经完成的份数和正在生产的一份的进度会保留。

每个占领任期只能建一座。攻防期间锁定建设；守住营地继续生产，失守清空该地库存和采集站。原营主夺回后可以再次投资。若首次建造回执丢失，可点「重试原请求」核对。

## 领取营地产出（签名内测 1039）

营主在指挥台查看该地资源的私仓余位、这次可入库的份数和领取后留在当地的份数。例如黄铜转运场已存 8 份结构材料、私仓仅剩 1 格，领取 1 份后，余下 7 份仍在转运场。仓满或当地无产出时，界面显示原因。线圈港按通用零件仓容独立计算。

若点击后未收到确认，可留在该指挥台点「重查本次领取」。服务器用原请求编号核对账本，已入账的同一笔可再次看到原收据；未执行的旧请求在占领任期改变后失效。[开发验收](../openspec/changes/archive/2026-11-09-m19-camp-claim-preview/verification/root-review.md)

## 从地图进场

私人基地 → 公开地图 → 黄铜转运场或线圈港。攻方先登记资格，再进入营地指挥台选择实际机体。指挥台依据服务端状态显示可用、受损和驻军机体。按「实时进攻」连接本机 camp 容器；房间首次验证攻击席位时，档案事务同时校验营地、时窗、归属版本、可用机体及 12 台／24 指挥点上限，冻结双方装配并产生派遣锁。先进入的编队获得该营地的唯一有效场次。第二支队伍保留机体和库存。

营主可在指挥台保存驻军。勾选可用机体后保存将占用同一台真实机器人；携带炮臂的机体可另勾选架设成固定炮塔，钻头机可机动驻防。解除炮塔架设并保存即可恢复机动；取消机体勾选并保存将结束驻防。收益与驻军面板在关窗后也可用。营地遇袭时，守方可到同一指挥台接管。无人应战时，房间只模拟实际部署的驻军和炮塔。初始的中立哨塔在首度易主后消失。

1030 内测版中，勾选机体时可以看到每台的实际装配点数，以及本人编队、已接收援军的台数和点数。合计以当前营地、当前攻守方向为准。把一台驻军架设为固定炮塔只计一次。恰好 12 台、24 点可以提交；超出时，指挥台显示超出的台数或点数，取消勾选即可重新调整。接回已有战斗席位仍可使用。

## 部署位置

机动攻守双方从核心圈外的四条集结线开始，守军略近。固定塔在守方前沿炮位架设。创建房间逐台核对边界、障碍、去重与到核心的路径；空营保留空席。旧进行中场次恢复时，仅修正在阻挡格内的历史机体。

## 指挥与结算

点击机体选中，点击地面移动，点击敌机集火。全选、前往核心、最近目标集火和战地维修也可从底栏操作。固定炮塔在原地转向，用真实炮臂属性结算；射线起点取当前朝向的模型炮口。每方可使用两次有效维修。单方在核心圈内累计 16 秒取得营地。时间上限 180 秒，进度相同守方保有控制权。攻方撤退、被全灭，或失联满 30 秒均判守方成功；守方暂时离开仍由已有驻军执行基础行为。双方短暂中断可回到原场次。

1029 内测版中，主攻指挥官失联时，服务器保留攻方已有的核心进度，停止为攻方累计秒数。援军可以继续指挥自己的机体。战斗、守方占点和整场时钟照常进行。原主攻方在 30 秒内重连并通过席位认证，可从原进度继续占点；若仍未接回就到比赛时限，守方保有营地。离线窗口会提示重新连接，取得有效席位后恢复指挥按钮，已结算的场次直接显示战报。恢复中的场次仍使用原绝对截止时间；房间进程异常终止时从最近成功保存的检查点恢复。[1030 安装与端口](android-private-beta.md#1030-本地内测)

SQLite 按唯一场次保存归属版本、不可变编队、场次结算及战损，并按真实参战机体更新累计，营地败方的私人库存、机器人和蓝图保持所有权。攻方若在同一个开放时段再次挑战，先完成必要维修并在地图重新登记；新的意图键可取得新资格。重复旧键取回原资格及已结算场次。已开始的对局保留冻结的结算期限。

黄铜转运场出结构材料，线圈港出通用零件。每人最多同时占两处，每地每 15 分钟产一份、各存八份。领取时按相应私人仓库余位结算，余量继续保存在原地。易主重置该地的产出时钟、库存和驻防。另一营地可在其开放时段独立开战。要调防，先在原地取消机体并保存，再在目标营地勾选同一机体。战中的机体须等权威结算和维修后再派。配置见 [营地产物](../services/profile/config/territories.json)。

档案接口使用 `/v1/camp/{node}` 及其 `reserve`、`garrison`、`claim` 子路径。旧客户端无节点的请求仍指向黄铜转运场。收据键重复提交返回该次实际到账量，跨地重用同一键返回 `key_conflict`。SQLite 现有表以节点或实体机体为键，本次沿用 v20。线圈港沿用已发布的轨道回收套件，码头绞盘所在的障碍和机动部署线均对应权威寻路格。

`python -B services/profile/check_two_camp_economy.py` 会对照 30、90 天的零地、单地和双地账本。固定每天一次领取、一次探索及一组资源消耗，第 15 天线圈港发生一次库存损失；输入和各项收支随测试脚本保存。可用 `check_two_camps.py` 检查调防、同机重派拒绝与跨地点收据，用 `check_live_camp.py --territories --godot <引擎路径> --evidence <目录>` 检查双地同时开战、线圈港接防和本机容器恢复。

## 运行和证据

```powershell
docker compose up -d --build camp profile
python -B services/profile/check_camp.py
python -B services/profile/check_live_camp.py --godot <Godot控制台路径> --evidence <证据输出目录>
```

调试客户端使用 UDP 24570，可由 CAMP_HOST、CAMP_PORT 覆盖。正式端点写入 [部署配置](../deploy/runtime_endpoints.example.cfg)。本地多窗口测试使用独立 Compose 项目和临时日程，覆盖中立占领、在线攻守、实体固定塔、容器重启及缺席易主。炮口与射线测量用 `Godot --headless --path game --script res://camp/tests/muzzle.gd`。同窗重试、收据幂等、并发排他、仓满处理与资格迁移的规则见[世界日程](world-calendar.md)。

房间每秒保存进度、接受指挥后保存检查点，终局先持久化再投递。档案从只读营地卷核验停服期间生成的终局，迟到回执按真实完赛时间处理。若宽限期结束仍无终局，收回派遣锁，保留上次可信进度中的战损。营地重新开放给下一场挑战。

签名 1011 的指挥台先读取所选地点的归属、席位和机体名单。等待中可返回地图；资料读取失败会显示重试，恢复后再显示适合当前身份的操作。营主只能领取本地库存内现有的资源。
