## 文档如何进入项目

1. **先定位。** 查上表及活动变更，优先更新同一主题的原文。同一条规则只在一个地方维护；其他入口链接它。用户新决定与旧文冲突时，在对应变更中列明差异，按已确认决定修订；未决定的保留为提案。
2. **再落位。** 产品与模块规划进入对应 Space 页面；可独立验收的新增需求先建 OpenSpec change；跨模块且长期复用的工程指南放在 docs/；Blender 源件、发布细节和资产网页契约在各自所属工程维护。此处只保存跨工程入口。
3. **同时登记。** 新增长期文档的同一变更里更新本表，说明触发场景、权威入口和维护位置。文档开头标明适用范围、状态（草案／生效／废弃）、维护角色；依赖版本时写明验证版本。临时日志和单任务证据由 tasks 链接，不逐条塞进全局索引。
4. **交接与验收。** 派发给子代理的任务写清模块、相关索引行、当前规格、可改目录、交付物和复测步骤。子代理提交文档与实现、自测证据；主代理从索引实际打开入口，复核内容与运行结果一致，给出通过或待修项。
5. **迁移与归档。** 移动、重命名或废弃文件时，搜索旧路径和标题，更新本表、任务及跨工程引用；废弃页指向替代入口。OpenSpec 归档前同步已接受的规格，核对历史变更仍可按名称查到。失效的本机路径先查工程位置；无法核实就标明缺口，不凭记忆重建规范。
