## 新资源与工具边界

提议唯一 namespace/Compose project 为 `punk-private-beta-1076-r5`，网段 `10.241.76.0/26`。六新命名卷后缀：`camp-battles`、`party-missions`、`solo-missions`、`player-profiles`、`room-auth`、`room-results`。启动前再次检查无同名资源；不得接上 R3/R4 卷。只生成 battle/buddy 两账号、两首机及一个新合作场次，使用本轮普通注册/命名 API 和游戏流程，不写 SQL、不导入旧档。

正式包端点固定：TCP 33380；UDP 33371/33372/33373/33374/33376。普通六服直接使用 33380，不起故障代理、不占 33382。验空库保留既有“72 表仅启动 key 一行”规则，再正常创建测试账号。六服实际 image ID/文件 SHA、env、配置、端口、协议、挂载、Compose 标签和容器 ID 必须入 operational gate；五路 transport 检查只证明握手，不签 gameplay。

预算：一个 `PunkLegion_FirstRoles1072` AVD，3072MB/4 cores、专属 ADB 5073、serial `127.0.0.1:5565`，以及一个 Godot headless peer。先做 peer 的冻结源准备/check-only，退出后才起 AVD；不启动编辑器，不与别的引擎任务并行。设备 owner 维持 28 分钟上限和原收尾余量；peer 维持 150 秒界限，超时是失败，不改游戏 30 秒规则。

本次只读资源检查：空闲内存 16,816,308 KiB；无 Godot/ADB/AVD 进程；33380/33382/5073/5564/5565 无监听；r5 容器/卷不存在。这个快照不替代执行当时的启动前检查，也没有创建待命资源。

可复用 R4 service 生命周期、identity、supervisor、设备触控和 phase/peer；不调用旧整套矩阵。实施前仅复制到新的 r5 输出和工具目录，保留原 r4 字节与执行报告。必须修改的最小范围：namespace/输出/清理归属；移除对旧 r4 容器 ID 的门槛绑定；新 operational gate 的文件名及 actor；下面的时敏流水和只读精确序号取证。所有改动先给 root 静态审查，记录前后源码哈希并做适用的工具边界自检，不引入新测试平台。

新文件用 `test-build-check-r5.json`、`test-direct-check-r5.json`、`test-execution-report.json` 等执行者名称，含 `actor=test_lead`、实际哈希/ID、scope 和不覆盖的范围。原 root package 签收可按相同哈希引用；不能生成新的 `root-*` 文件或借 `--root-approved` 自称主验。主代理放行写独立审批记录，工具授权门槛与测试事实分开；最终 root 签收另栏另文件。

## 时敏流水与断言

1. 先验工具和资源门槛、保护包/515 清单、六新卷空库与当前平台基线，再生成两账号。记录 initial ledger。手机正常登录并创建队伍、选择首机，读取邀请码；buddy 普通 API 加入/准备。此时不开战，可逐张核手机当前 PNG/触控坐标。
2. 在同一段有界宿主编排中：手机实际 Launch 点击 → buddy 普通 GET 取票 → 唯一 peer 进程启动 → 连续保存手机早期帧/peer 状态与服务 JOIN 日志。中间不等待模型或 root 读图。保存各 UTC/monotonic 时刻，实际 JOIN 差必须小于 30 秒，真实 started/online2/各有己方存活机体；不能只凭屏幕 2/2 签通过。
3. 双方各一次正常 route。手机通过实际控件触控，peer 通过已存在的 flag/真实客户端网络 command。保存手机输入、实际战场反馈、peer personalized accepted_seq，并在撤退前只读复制该场当前 `.save` 及 progress 文件。`progress.commanded=true` 不足以证明精确 seq；生产 `PartyMission.personalized` 只暴露本人 seq，`save_party().orders` 才包含各 owner。拟在 peer/AVD 退出后用单独一次有界 headless 只读解析保存副本，导出 orders/issued/owners/participating；不改生产、不在活动场次多开引擎、不把构造状态当真实权威反馈。原始副本及解析工具 SHA 一起保留，票据/凭证不进公开日志。
4. 首位正常撤退后确认其 receipt 和伙伴仍可继续；另一位随后正常撤退。应在 peer 150 秒前完成真实链，不以最后存活单位死亡替代撤退。双方 individual receipt、room progress、SQL 按同一 mission/owner 对上；手机实际个人战报，buddy 用普通 API 读取自己的结算，不用房间汇总代替个人结果。
5. 按 initial→entry→settled→collected/finished ledger 对账：各 owner 一笔 entry_receipt/一次费用、各一个非空个人结果/收据、无重复入场；战损/奖励与个人明细一致；机器人 task/assignment 释放；累计参战/击败/实际维修与本场贡献一致。没有发生的击败或维修不强造正数，本轮不新增机器人详细战斗日志。
6. 手机正常战果确认和收工返回基地，保存最新累计；force-stop 后重新启动同正式包、同本轮账号，核基地/档案/个人已结算状态，不产生新出征或重复扣费。cold restart 是应用进程冷启，明确不宣称手机重启/性能验收。完成收工和回读后再结束设备 owner。

每步保存原始退出码、截图/输入、请求/API状态、日志和逐 owner SQL；不靠最终 summary 的 true 覆盖中途错误。任一实际断言失败保存局部事实，停止后续串行场次；不延长等待、重开新号或重放旧战报求绿。若精确序号快照方式不可行，先报 root 定案，不把布尔 commanded 降格当通过。

## 收尾与交接

成功、失败、超时均先保存证据，再按实例身份关闭 AVD/专属 ADB/peer/采样器及子树。记录 PID+启动身份、AVD+serial、Compose 实际 ID/标签/配置、端口、关闭动作与原始终态。临时凭证按已知本轮文件清理，日志不记录密码或 token。

失败时原配置 `compose down` 删除本轮六容器和专属网络，保留六卷/镜像/AVD/证据；`docker ps -a`、专网和端口复核为零，不留已退出容器。成功时设备/peer 同样退出；六服只有 root 明确接手且给出试玩用途才保留，否则也删除容器/网络并保卷。1075 试玩、OGame 和资产库不在本次补验清理范围，退役切换由任务 3.1 另行签收执行。
