# 测试运行报告模板

状态：模板。维护角色：`test_lead`。复制到本次唯一运行记录后填写；未知或未执行项明确写明，不填默认通过。

## 范围与执行身份

- Run ID、日期、模块、OpenSpec change与要求条款：
- 测试代理、功能开发代理、主代理审查人：
- 玩家场景与通过条件：
- 本轮结论：通过／产品失败／工具失败／环境失败／观察失败／部分完成／暂停／未运行。

## 测试数据与执行

- 入口与调用夹具审查结果，是否排除了迁移/旧快照恢复分支：
- 本轮新库/新卷、新账号/场次及正常生成路径；内存夹具说明：
- 实际命令、参数、开始/结束时间、退出码和原句柄：
- 框架测试数、断言数、失败数、跳过数与原因；空用例处理：
- 实际关键步骤、请求次数、权威接受指令、个人费用/收据/任务状态等适用断言：
- 原始日志、截图、HTTP/SQL/场景状态与结构化报告链接：
- 负对照及其失败信号（框架或运行器接入时填写）：

不要记录密码、Authorization、票据或完整私有输入；需要关联时记录测试owner、请求ID和安全时间信息。

## 失败与剩余缺口

逐项记录首次失败、证据、分类、影响的断言、修订方和复验范围。保留后续尝试，不能覆盖首次结果。进程退出0、有收据或框架绿灯均须结合玩家通过条件判断。
