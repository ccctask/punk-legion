# 本地玩家档案

状态为生效。适用于 M07 开发服及后续使用同一 SQLite 的模块，维护角色为服务端开发与验收代理。已验证 Python 3.13 容器、Windows Python 3.14 与 Godot 4.6.1。

## 从游戏进入

签名内测 1009 直接在私人基地注册或登录。查看已有机体、库存与服役累计时，打开「基地菜单」→「指挥官档案与机库」。Godot 桌面调试时在项目根目录运行 `docker compose up -d --build profile`，从机库试车台点击「档案」。账号为 3–32 位 ASCII 字母、数字、短横线或下划线，密码 8–128 个字符。注册得到一台有唯一编号的机器人。已登录账号可改机体名称、派遣与取消或完成探索、驻防、援助和维修任务。离开档案后重新登录可查看原状态。另一实例以相同账号登录后，原实例在下次请求时提示重新登录。M07 任务完成由开发服按钮驱动，尚无业务奖励。

默认地址为 `http://127.0.0.1:24670`。安卓 USB 调试可运行 `adb reverse tcp:24670 tcp:24670` 再使用同一地址。桌面可通过 `PROFILE_URL` 设定默认地址。仅供本地开发验收的明文 HTTP，面向真实用户的受保护传输与正式渠道登录见 M23。

## 服务契约

注册和登录分别 POST 到 `/v1/accounts` 和 `/v1/sessions`，JSON 字段为 `name`、`password`。成功响应包含一次签发的 `token`，后续请求用 Authorization Bearer 传递。登录替换旧会话。GET `/v1/profile` 返回 `account` 和 `robots`。每台机体含永久 `id`、`name`、`task`、`assignment`；后两项在待命时为空。

对 `/v1/robots/{id}/rename` POST 名称。对 `assign` POST `task`（expedition／guard／aid／repair）。对 `finish` POST 当前 `assignment` 与 `outcome`（completed／cancelled）。成功后读取响应中的档案。401 表示需重新登录，404 表示当前账号无法访问对象，409 表示操作冲突；刷新后以最新档案为准。数据库写入端在 `services/profile/server.py` 共用 `transaction(path)`，在同一事务读取、校验、变更和返回快照。

## 备份与恢复

以下 PowerShell 命令在仓库根目录执行。备份包含账号敏感数据，保存到仅负责人可访问的位置。备份命令拒绝覆盖已有文件。

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
docker compose exec -T profile python server.py backup --file "/data/profile-$stamp.sqlite"
docker compose cp "profile:/data/profile-$stamp.sqlite" ".\profile-$stamp.sqlite"
```

恢复时先停止服务，保留卷。以下步骤从卷内备份恢复到一个新文件，原文件改名留作回退；将示例时间戳替换为备份实际时间戳。若从外部文件恢复，可先在容器仍运行时用 `docker compose cp` 把备份放进卷内。每步确认退出码为 0 后执行下一步。

```powershell
docker compose stop profile
docker compose run --rm --no-deps profile python server.py restore --file "/data/profile-$stamp.sqlite" --db "/data/recovered-$stamp.sqlite"
docker compose run --rm --no-deps profile python -c "import os; from pathlib import Path; p=Path('/data/player.sqlite'); old=Path('/data/before-$stamp.sqlite'); assert not old.exists(); os.link(p,old); os.replace('/data/recovered-$stamp.sqlite',p)"
docker compose up -d profile
```

恢复会校验数据库完整性并撤销备份中的会话，玩家重新登录后查看机体和任务号。SQLite 使用默认回滚日志；运行中使用 SQLite 在线备份接口。数据版本取自 PRAGMA user_version，服务拒绝未知版本；未来升级须先制作备份、编写并验证迁移，再提升版本。

## M08 仓库与演习结算

仓库从档案登录后进入，点击「查看库存」读取资源、已掌握的蓝图、逐件部件和最近 30 条回执。每条业务的完整回执保存在 SQLite。原型以结构材料／通用零件／能源为三类库存，初始 12／6／5，容量 40／24／12；部件上限 24。炮臂消耗 3 材料和 2 零件，演习票消耗 1 能源。目前数值用于工序与并发测试，持续资源产出留待后续经营模块配置。

`GET /v1/inventory` 返回库存；`POST /v1/inventory/craft` 传 `key` 和 `recipe`；`POST /v1/inventory/admit` 传 `key`。同一账号重试须沿用业务号和原参数。每个账号只保留一张待用票，可从仓库找回后返回试车台。房间根据演习结果向档案投递结算，SQLite 使用票与唯一场次保证每个账号每场仅入账一次。服务授权 key、票和账号 token 均不应写入普通日志。维护档案库前先停房间，保留房间待投递卷与授权卷；灾难恢复需要同一恢复点的档案和房间队列备份。

M07 数据版本 1 在启动时事务升级至版本 2；现存账号保留机体与任务并各领取一次初始库存。备份命令兼容版本 1。服务端故障与重试可分别用 `python -B services/profile/check_inventory.py` 与 `tests/room-ledger-smoke.ps1 -Godot <Godot路径>` 验证；UI 可用 Godot `--headless --path game --script res://profile/tests/inventory_ui.gd` 验证。这两项 HTTP 与房间测试使用隔离库，UI 脚本会在目标开发库留下一个测试账号。
## 私人基地复测

私人基地的建造列表可选「军营机库」。在与道路相邻的 2×2 空地预览并确认，消耗 1 份结构材料。建造模式中点击已建军营可查看本人机体、状态与剩余机库容量；切换「设计与制造」按已有方案招募新实体。离开工坊返回原基地。多栋军营共享同一份 18 台机库，建筑本身不消耗额外供电。已有账号仍可从档案直接使用工坊。朋友参观基地时仅可查看军营。

进入机库「档案」，登录后点「私人基地」。服务器已有账号材质库存即可开局。初始格网 12×9，坐标从 0 起；左上定位建筑，道路四向相邻。初始核心位于 (1,2)，入口为 (0,4)，主路延伸到 (9,4)。每个设施花费 1 结构材料，移动、铺路和移除道路免费。核心供电 6，需求依次为冶炼 2、仓库 0、装配 2、修理 1、固定炮塔 2。处在供区内的设施按建造顺序分配余量，覆盖和容量的判定见本页[私人基地供能布局](#私人基地供能布局)。上述为测试数值。

在建造模式依次放置冶炼 (3,2)、仓库 (5,3)、装配 (7,2)、修理 (1,5)、炮塔 (3,5)。预览显示占地、费用、道路与停电数量，确认后写入账号。此时炮塔停电、实耗 5/6、布局 v6。封存后，将核心移到 (5,5)，当前变为 v7，封存仍为 v6。「刷新布局」返回当前可编辑版本。占道或建在道路无法到达的位置会显示错误，材料与原布局不变。

服务端入口为 /v1/base，另有 preview、edit、freeze 与 snapshots/{id}。版本与写入业务号保护并发编辑；只允许会话所属账号读取、操作和回看封存。M16 可复用封存后的不可变布局。设施使用六种组合灰盒，本机现有发布的履带机没有可替代这六类设施的可用建筑发布版本，正式建筑资产尚待建模验收。

`python -B services/profile/check_base.py` 使用全新临时库运行两个账号、冲突编辑与跨进程重开。追加 `--godot <控制台程序路径>` 从真实档案界面跑屏幕坐标点选；追加 `--capture <绝对PNG路径>` 打开渲染窗口并保存实测画面。

## 自有机体工坊（M09）

从指挥官档案进入「自有机体工坊」。在设计页选择底盘、动力、传感器、工具和可选功能件，比较整机的材料消耗与指挥点，保存版本后按该方案制造。每台新机与各个实装部件都有独立编号。战术目镜与钻头争用精密总线。未掌握钻头配方时可先保存合法草案。机库最多容纳 18 台，背包可存 24 件闲置部件。

在「机库与实装」可逐槽换装。从 1039 内测版起，还可选中目标机体，点「预览套用」查看整套方案：相同部件沿用原件，需要替换的槽位显示将装入的实体编号，以及拆下的普通部件或救援件会如何处理。缺件时可返回机库准备。只有确认才会应用；若预览中的备件已用在别处，要重新预览。任务中的机体须先结束任务，未装齐的机体保留身份。[整套换装验收](../openspec/changes/archive/2026-11-09-m09-preview-owned-refit/verification/root-review.md)

账户设计及版本保存在 designs；机体身份沿用 robots，逐件库存身份沿用 parts，mounts 为机体插槽与唯一部件的绑定。M09 迁移保留旧机体名称、编号、任务、可用库存、已有余额和回执，为旧机体补上基础实装。制作费用和拆装出入库在同笔 SQLite 事务写入原账本。

`GET /v1/workshop` 返回方案、机库、实装和可用部件。`POST /v1/workshop/design`、`build`、`refit` 分别保存新版本、制造和换件。换件须提供请求见到的原部件 ID；新件传空字符串表示拆卸。`POST /v1/workshop/deployment` 按 `robots` 中的真实 UUID 提取待命、完整且归当前用户的编队。出战最多 12 台及 24 指挥点。返回的 `units`、`inventory` 可传给 Godot 的 Rules.validate_squad。在权威参战事务中使用相同的 workshop.deployment_for 与 workshop.owned_robots 校验并冻结快照。


## M10 机体服役累计

从「基地菜单 → 指挥官档案与机库」选中自己的机体，查看服役累计。档案按永久机体编号展示三项：实际参战场数、末击击败的敌机数，以及这台机体在战斗中实际为友机恢复的耐久。新机三项均为零，同名机体分别统计。改名、换底盘或更换部件后累计值仍归原机。

## M12 生产与研究

档案 → 私人基地 → 生产与研究。核心每小时产 1 能源，冶炼每 20 分钟产 1 结构材料，装配每 30 分钟产 1 通用零件；每座设施单独计数，停电或手动暂停时停产。新账号从注册启动生产钟，升级时既有账号按照当前布局从上线时点启用生产。已累积的不足一周期的工作量在断电期间保留。使用布局「切换供能」可让出原有电量或恢复供电。

材料／零件／能源的初始待领槽位为 4／3／2，每个有电仓库增加同样数量。各资源还受库存现有空位与 12 小时离线封顶约束；仓满期间不积存可补领的工作量。领取把产出写入账号物资账本。已供电的装配车间可用 2 份结构材料和 1 份通用零件提前研究钻头制造配方。也可累计三次锈轨个人胜利免费掌握同一配方，工坊会显示个人进度。掌握后可制造钻头机体，研究按钮停用。精密铸造消耗 2 零件与 1 能源，使冶炼速度翻倍。以上速率、费用和容量为原型值。[探索掉落与配方](solo-expedition.md)

`python -B services/profile/check_production.py --godot <控制台程序路径>` 在隔离 HTTP 服务用可控测试时钟核对短时、24 小时、3 天、7 天、满仓/余一格、断电与恢复、并发和重开；客户端从真实经营面板领取、研究，在档案工坊造出钻头机器人。客户端没有推进服务器时钟的入口。

## M21 工坊模拟商店

适用于本机 Compose 封闭测试。档案 → 自有机体工坊 → 涂装与方案栏商店。基础黄铜免费。薄荷珐琅每账号一份，6 模拟点；方案栏每份 3 模拟点，免费 6 格，可再购 2 格。这些价格仅用于测试。容器开关 `PUNK_TEST_PAYMENTS=1` 启用模拟下单、付款及退款；设为 0 后保留查单与既有外观装备能力。服务端进程未设置此变量时，模拟付款关闭。

1. 商店按同次档案读取的自有机体底盘、已装部件与空槽进行试穿。切换机体或涂装可直接预览，返回工坊恢复先前的草案、底盘预览或收藏筛选。创建订单后选「模拟成功并发货」并提交，选择机体、涂装并装备。取消或失败后可重新下单。选择「模拟已扣款、暂缓发货」，退出重新登录后可在同一订单提交「查询支付结果并补发」。退款会撤销权益，正在使用的机体恢复基础色。战斗按入场时冻结的装配和涂装进行。
2. 工坊保存同名草案会新增历史版本并沿用同一常用位置。新增、替换、移出在档案事务内更新。被移出的版本仍可查看。退款回落到有效格数，超出的配置可预览或替换到有效位置。剪贴板导入先预览，实际换装通过机库与实装中的应用按钮，逐槽核验账号闲置部件。
3. 常规验收使用全新测试档案。运行[购买、补发与退款回归](../openspec/changes/archive/2026-11-09-m21-equipped-paint-preview/verification/root-orders.py)和[实物试穿回归](../openspec/changes/archive/2026-11-09-m21-equipped-paint-preview/verification/client/run.py)。运行 `Godot --headless --path game --script res://store/tests/battle_paint.gd` 对照同机体基础/薄荷的炮口、射击、装甲边界、数值与战果。`python services/profile/check_live_camp.py --godot <程序> --paint-check --evidence <目录>` 可重演带实装涂装的双席营地争夺，临时容器与账户隔离。

## 功能接口与战地维修臂

从 1042 签名内测版起，泵房个人首通也会回收一件真实维修臂，背包满时可在常驻机库补领。工坊会标出回收物编号，装配仍使用 AUX 功能槽。[来源与领取](world-calendar.md#雾钟泵房合作遗迹)

档案登录后选「查看库存」，用 2 结构、2 零件制造一件维修臂。打开机库实装，在目标机体的「功能接口 AUX」选该实物并安装；拆卸会保留原部件编号并退回背包。也可保存含维修臂的整机方案再制造。仅加装此部件时，整机制造多耗 2 结构和 2 零件。原有三个必装接口保持兼容，功能槽允许留空。装上会增加 1 载重、1 功耗、1 热量和 1 指挥点。模型预览使用资产库的 PL_HeavyEscortKit / MedicRig。

独行探索可派自己的两台机体，好友合作可派各自的机体。支援机自动选择 5 米内的其他存活友机，先保当前耐久不超过 35% 的危急机体，再帮仍受火力压制的友机；同优先级按缺失量选取。缺少 8 点立即启动。轻伤而未濒危时，等待停止受击 6 秒再补。每次至多恢复 10 耐久，间隔 6 秒，每场 4 次，消耗仅在实际恢复时发生。战场显示实装维修吊臂并在施修时短暂显示绿色光圈。战斗结算后，施修机的服役累计增加它实际为友机恢复的耐久，工坊检修仍在机况页查看。

桌面复验可运行 `python -B services/profile/check_field_repair.py --godot <Godot控制台程序> --output build/field-repair-review`。脚本在独立容器中用三份客户端完成一场双机独行及一场双账号协作，以只读副本复投真实报告并核对双方。独立边界可运行 `python -B services/profile/check_field_repair_rules.py` 和 Godot `--headless --path game --script res://owned/tests/field_repair_rules.gd`。

## 私人基地的模块化防御平台

开发版在野袭结算战报中分别列出本场实际掠夺，以及驻防机受损时的维修估价。从私人基地或指挥官档案里的基地进入战报，点「查看驻防机当前机况」可按本场登记的机体编号查看，即使机库里有同名机体也能区分。查看只读取当前机况；点「入列维修」后才按当前报价扣料。修好后重看同一份战报仍保留当场战损，机况页显示当前待命。无人驻防或驻防机未受损时，战报没有这项入口。 遇到短暂连接失败时，战况页和机况页先快速补读最多两次。已显示本场预警或实战画面的战况页会保留最后确认的画面，此后每约 10 秒查询一次，恢复连接后可直接看到同场结算。玩家也可点「刷新战况」提前查询。首次载入、保护期和机况页在快速补读耗尽后等待手动重试。登记驻防后如果回复中断，界面会先查本场已登记的机体；只有核实尚未登记后才可再次手动确认。

1034 签名内测版在野袭预警中显示驻防候选的名字和机体编号。刷新名单时会保留选中的机体；若它已经出征或送修，重新选好后才能登记。

1029 内测版计算袭击财富时，私人产线已经完工、可以领取的物资与主仓同类资源等值。在预警前后领取同一批货，敌军数量相同。敌军仍只会掠夺主仓里超出保险的部分；打完以后可以照常领取产线上的货。[1030 安装与端口](android-private-beta.md#1030-本地内测)

含配电柱的冻结布局可在同一次野袭中查看预警、现场战况与战后回放。扩充设施时需核对档案设施目录、Godot 基地模型及名称，并经正常基地入口复验整组设施。[八种设施与配电柱回放验收](../openspec/changes/archive/2026-11-09-m16-raid-relay-layout/verification/README.md)

### 野袭后的设施抢修

开发版中，野生机器人突破防线且防守失败时，最多有一座冶炼炉或装配车间停工。敌机优先破坏突入路线旁、开战时有电且仍在基地的设施。战报写明受损建筑和当时的位置，返回基地可点建筑查看抢修报价。移动建筑后，损伤随同一座建筑保留。

抢修消耗 1 结构；也可以等 10 分钟免费修复。计时从这场战斗的实际结算时刻开始，离线也计时。已经生产的物资和生产进度保留，其他有电设施继续工作。装配车间停工期间，研究需另有一座正常工作的车间。缺电设施修好后，恢复供电即可生产。战后守军维修报价、设施抢修报价和实际掠夺的合计上限是 4 份资源。

## 野袭失守后的威胁减免

私人基地每次野袭由服务器结算。从结算时刻起，失守有 48 小时整备，即使当场掠夺为零也适用；守住核心有 24 小时整备。整备期间重登或重看战报沿用原定期限。若一直离线至期限已过，返回时另获 24 小时。开发版的供电雷达站在正式预警前 90 分钟内报告信号。服务器从原定正式预警时刻起留出 3 小时整备，开战前成功保存的防线与已登记守军用于本场。中途重登沿用同一时刻，例如预警发出 2 小时后返回，距开战还有 1 小时。签名 1072 沿用其发布时的 30 分钟。

开发版中，从私人基地打开「野生机袭击预警」可查看本场威胁点数。首次防守或上一次守住核心，用本次财富对应的基础点数。上一次私人基地失守减 1 点；如果当时登记的那台守军在新预警发出时仍待修或正在维修，再减 1 点。每场最低 2 点。预警有实际减免时会说明原因及最终点数。

例如基础为 5 点，上次失守后原守军仍待修，本场为 3 点。若在预警前已修好，本场为 4 点；若收到 3 点预警后才修好，本场实战和回放仍为 3 点。只看最近一次已结算的私人基地防守，连续失守只算最近一场。公开营地、探索的败绩与主动派遣机体均不计入此项减免。

签名安卓 1045 在私人基地的袭击警报中标出来袭入口。地面箭头沿本场行军道路指向核心；在预警期修改布局并保存，重新查看同一场即可看到新路线。开战后按最后锁定的路线防守。同一预警列出来敌与威胁预算。预算不足 4 点时均为巡逻机；达到 4 点可遇到装备钻头的重型拆解机。每台重机占 2 点，耐久约为巡逻机的两倍，每两秒前进一格。[1045 安卓实战](android-private-beta.md#1045-本地内测) · [改道与实战轨迹](../openspec/changes/archive/2026-11-09-m16-raid-approach-preview/verification/root-review.md)

### 野袭中的回收蜂群

开发版中，本场实际威胁预算达到 5 点时，可能遇到一组三台回收蜂机。预警会显示蜂机数量，三台各占 1 点、同时进入道路，以巡逻机的速度向核心前进。每只耐久约为巡逻机的一半，炮台可逐台击落。预警期间可沿箭头检查射界和供电，调整炮位并保存；即使只有一只穿过火线抵达核心，也会单独计作一次突入。战后播放回放可核对击中的蜂机与漏过的数量。

签名内测 1028 从私人基地进入「野生机袭击预警」，可在登记驻防机前查看当前主仓库存超过保险额度的部分，以及本次失守最多可能被掠夺的总份数。例如结构材料超保 3 份、通用零件超保 2 份时，失守合计最多被掠夺 3 份。在工坊消耗材料后刷新战况，预警会按剩余库存重新计算。战后防守记录列出实际被掠夺的资源和维修成本。防守画面只显示本场已登记的守军，返回基地后恢复当前布局；首机仍在役时会重新显示其模型及名牌。[1028 保险额度与历史记录](android-private-beta.md#1028-私人基地防守服务已停止)

在私人基地建造列表选择「防御平台」，点道路旁空地预览并建造。新平台初始为空；建造模式点已建底座即可查看当前实体和背包部件。气炮用于拦击野生机，维修臂用于射程内受损的驻防机（每场至多四次，最多恢复实际损伤）。钻头、机体头部及锅炉不适配固定底座。供电和射程均由服务端执裁。炮台实弹与青绿色维修光束可在防守回放中分别查看。

装配、替换、拆卸和移除均使用相同部件实体 ID；同一件不能同时属于平台或机体。拆卸或移除时背包已满会保留现状；替换可以对换装备。制造和背包限额与机库共享。开发版中，野生机预警先确定本场威胁与开战时刻。点「回基地调整防线」修改道路、供电或平台挂件，开战前由服务器成功保存即纳入本场，无须另行留档。回到预警可逐格核对已保存的平台部件与实际供电。到达服务器开战时刻，本场防线锁定；道路和供电仍可在基地保存，供之后的袭击使用。参战平台的实物装配锁定至结算，战后可拆下用于本人机体。平台件按与背包及机体相同的标准计入财富。存档 v16 的旧式炮塔保留原有火力；首次自行换装后变为新式插位，原装塔体不能拆出一件可领的气炮。历史回放沿用冻结配置。

## 机体职责与战前指令

进入「档案 → 机库与实装」，选择一台机体并展开「战前职责」。可将它分入前排、火力或支援，选本账号一台其他机体作为护卫对象，指定交战距离、索敌偏好和低耐久回撤阈值，然后点「保存到此机体」。默认推荐维修臂归支援、钻头归前排、其他机体归火力。保存后使用永久机体编号关联，改名、换工具或调换编队顺序仍保留自定设置；「恢复装配推荐」会重新按当前部件选组。两种操作都不消耗物资。作业中的机体须返回后才能改令。

| 行为 | 玩家可选项与结果 |
|---|---|
| 护卫 | 自由行动或指定同账号友机。与护卫对象偏离约 4 米后向它靠拢。没有一起出战、倒地或已退场则恢复自由行动。 |
| 交战距离 | 默认在武器射程内开火；贴近时尝试进入 1.8 米（近战武器仍受自身射程约束）；保持射程边缘时避开过近的对手。 |
| 索敌 | 最近敌机、耐久比例最低、优先威胁护卫对象或本机的敌人。同等优先级选近敌。 |
| 回撤 | 持续交战、剩余 25% 或 50% 耐久时尝试拉开距离。仍处于同一战局；正式撤离沿用战场按钮。固定炮塔留在固定位置。 |

战场的前排、火力、支援按钮只选本席可控制且存活的机体，仍可全选、点选和手动移动或集火。点击无成员的组会得到空选择。手动移动执行至目的地；指定集火维持至目标失效或新命令覆盖。支援机的维修属于独立自动能力。战场载入时使用出击快照中的规则；途中断线重入后继续使用原快照。

档案 schema v17 用独立可选行保存策略；旧机体和旧房间快照可按原装配出战。正常双窗口与单人触控复验运行 `python -B services/profile/check_squad_orders_live.py --godot <Godot控制台程序> --output build/squad-orders`；营地终局和重启执行 `python -B services/profile/check_live_camp.py --godot <Godot控制台程序> --orders-check`。


## 可更换底盘与实机装配

开发版的「机库与实装」在选择背包部件时显示当前与换装后的最大耐久、移动速度和出战指挥点。以履带、双目和气炮为例，普通锅炉机为 70 耐久、3.6 米/秒、2 指挥点；装上加固锅炉后为 155 耐久、2.4 米/秒、3 指挥点。选件可反复比较，确认后才占用实物。开发版遇到换装回复中断会自动核对原操作一次，持续未确认时可在选件旁重试，重新打开机库也会继续核对。[回执恢复主验](../openspec/changes/archive/2026-11-09-m09-workshop-refit-receipt-recovery/verification/root-review.md)

档案 v19 给机体登记底盘类型，已保存方案也带有底盘。旧机体、旧方案和旧战报缺少类型时均按履带读取。命名机体的稳定 ID 与各槽装配件的 ID 相互独立。

| 基础底盘 | 指挥点 | 载重 | 基础耐久 | 移速（米/秒） | 受击半径（米） | 标准机制造费（结构／零件／能源） |

| 履带 | 2 | 6 | 70 | 3.6 | 0.60 | 3／1／1 |

从档案进入真实工坊。设计页选底盘后保存方案，制造页按保存的版本扣费。机库页选一台待命完好的实体机，选择目标底盘，核对现有装备、费用和载重，再按「确认更换底盘」。双向转换都消耗 2 结构、1 零件、1 能源；旧底盘拆解，装配、名字、职责、涂装与登记号保留。超载时先拆件或换轻件。应用异底盘的方案需要先完成换底盘。每一笔转换沿用工坊回执，变更接口为 `POST /v1/workshop/chassis`，请求字段为 `key,robot,expected,chassis`。普通账号可用初始材料取得双足。

两个底盘的四槽遵循同一接口，工具的火力与能耗取自实际装备。按编队实际花费检查 12 台／24 点；基础履带最多 12 台，基础双足最多 8 台。已启动场次从冻结清单取底盘、部件、名字与指令。更换底盘后，机体保持原有服役累计。试车台的装配试战可自由试两种底盘，实体制造与消费发生在档案工坊。

## 脉冲干扰器

在玩家档案仓库用 2 结构、2 零件制造一个实体干扰器。进入自有机体工坊，选择实体机体的 AUX 功能槽安装，原有维修臂须先卸回背包。履带和双足底盘共用此接口。干扰器占 1 点编队预算，首轮调试参数为射程 6、4 次能量、同一发射器至少相隔 5 秒。

当敌机进入射程，脉冲使其下一次已排定的武器与维修各推迟至多 1 秒。敌机推动履带或迈步、接受手动指令的过程照常进行。目标立即获得全队共享的 4 秒保护，其他发射器在此期间不消耗针对它的脉冲。若没有待修对象，此次维修限制在 1 秒后结束。攻击决定和恢复数值已经入账后，脉冲不会回改结果。

蓝色光环和「发出脉冲」标出来源，紫环与倒数标出受影响机体。保护截止时刻随当前战场状态恢复。演习、单人和组队探索、营地争夺共用 Godot 权威战斗；秘宝使用自己的固定步进战斗，同样执行双动作延迟和共享保护。

私人平台的 AUX 也可安装此实物。当前野生机器人碰触核心造成损害，不会使用武器或维修。携带干扰器的驻防机照常用自己的武器拦截。没有可延迟动作时，防守记录不计干扰。

### 首次探索扩地

签名内测 1012 中，私人基地的东侧三列在初始状态显示为灰色。玩家亲自打通锈轨回收场，回到基地即可使用这 27 格，基地由 12×9 扩至 15×9。单人和组队均以档案里本人的胜利回执为准；自动战斗也可获得。组队撤离、失败和普通派遣不会解锁。已通关的老账号下次读取基地时自动获得土地。扩地免费，之后在新地上建造设施仍按原价扣料。原设施、道路、供电和机体留在原位，已封存的防守布局保留当时的范围。

## 私人基地修理站

## 私人基地供能布局
