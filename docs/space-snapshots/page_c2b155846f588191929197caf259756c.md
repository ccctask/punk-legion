# 一 阅读顺序与产品边界

先读第二、三节理解导航，再按第四节的页面编号制作线框，第五、六节核对规则和完整任务流，最后补齐第七至十节的状态稿与组件。工程核对使用文末入口证据附录，设计师不必按脚本目录组织页面。

沿用[主策划案](https://chatgpt.com/space/page_6aefe98e48fc8191879bf4294ba5ae00)的七类核心界面：基地、装配车间、机器人档案、世界地图、编队、战斗、战报。现有功能继续归入这些玩家任务，不为每个脚本增加一个一级菜单。

- 轻度玩家主要走私人基地和PvE探索，每天目标节奏15–30分钟；公开营地和秘宝是自愿承担风险的支线。

- 私人基地只面对野生机器人袭击；公开营地会被其他玩家攻占；秘宝不能占领。三种风险必须在入口就分清。

- 方案、实体部件、拥有的机器人、出战编队是四种不同对象。保存方案不造机，分享方案不送部件，勾选编队不改变机体所有权。

- 机体保留自己的名称与身份；档案只突出参战场数、击败数、实际施修量三项累计。没有性格、对话或逐秒服役日志设计任务。

- 商业化只围绕现有外观和方案栏。当前为模拟订单，不把真实支付、付费战力、抽卡、通行证或渠道账号画成已实现能力。

- 可爱工业玩具是视觉方向。建筑、底盘和武器的识别优先于装饰；外观不得遮蔽实际武器、体型和战斗提示。

# 二 全局入口结构

## 2.1 导航基线

```text
启动 → 基地背景上的登录／恢复 → 首机命名 → 私人基地
私人基地
├─ 建设：设施目录、布局编辑、道路、供电、已建设施详情
├─ 机库：机器人、实装、方案、整机制造、部件仓与制造、维修
├─ 出征：PvE探索、合作、世界地图、进行中的活动
├─ 好友：关系与申请、参观、援军、装配分享
├─ 商店：外观、方案栏、自己的订单
└─ 基地菜单：账号、声音、帮助与反馈、独立内测工具
基地情境入口
├─ 当前指引／今日目标／离线摘要
├─ 产出可领、研究、待修机体、受损设施
├─ 野生袭击预警／防守结果
└─ 自有公开营地遇袭 → 回到对应营地
```

建设、机库、出征是主操作，好友是次级常用入口；商店和设置降低视觉权重。商店不挡住出征，诊断不占基地首屏。基地里的军营、修理站、研究站等建筑仍可作为同一功能的情境入口；快捷按钮与建筑打开同一页面，不能形成两套库存或维修状态。

“出征”按玩家意图组织：周边PvE关卡、邀请／寻找队友、公开世界。世界地图仍能显示泵站等PvE事件；它是同一活动的另一条路径，不新增一份活动。进行中任务优先显示“继续原场”，不能让玩家误开第二场。

## 2.2 基地首页布局建议

横屏首屏保留可交互的基地场景。建议建设和出征分置底部两侧，机库、好友作为较小但清楚的快捷入口；具体左右位置由小屏原型验证后定稿，不把位置固化为业务规则。

| 区域 | 展示内容 | 操作与约束 |
|---|---|---|
| 顶部信息带 | 结构材料、通用零件、能源及容量提示；账号入口 | 点击资源看库存／来源；不常驻铺开所有收支文字 |
| 中央基地 | 建筑、道路、机器人名字及选中反馈 | 浏览与建设模式明确分开；浏览点建筑看详情，建设模式才操作布局，这属于目标交互调整 |
| 主操作区 | 建设、机库、出征 | 图标加文字，出征不能藏在长滚动表单底部 |
| 情境待办区 | 当前引导、可领产出、待修、预警 | 可收起；只提示真实待处理状态，不把每个系统做成红点 |
| 次级入口区 | 好友、商店、基地菜单 | 数量受控，不能与战斗／建造主按钮争夺层级 |

首次登录、命名、网络恢复使用基地背景上的任务层；完成后让出基地画面。日常进入不再次经过试车台、IP表单或版本信息页。

# 三 页面组织原则

一个页面只回答一个主要问题。机体大图和装备槽回答“这台是谁、装了什么”；编队回答“本次带谁”；制造回答“我要新造哪台、花多少”。不能用一个大下拉框同时承担三件事。

大范围选择用卡片列表或分栏全屏页；与当前对象紧密相关的少量操作用详情抽屉；有消耗、不可逆后果或风险承诺的动作有独立确认层。确认层不再嵌套另一个确认层。1084正常页面进入、回前台及到期自动读取，不把“刷新／同步日程”画成日常动作；真正读取失败才给重新连接或原操作恢复，不能要求玩家反复刷新才知道是否成功。

返回规则统一：普通详情回来源并保留选中项／列表位置；草稿未提交时说明放弃草稿；请求已发出时不能把“关闭”写成“取消交易”；已进入活动时区分离队、撤退、撤离和仅关闭页面。联机战斗不因打开菜单而承诺暂停。

# 五 编队与活动规则 必须按模式显示

以下是当前原型值，用于设计真实状态和容量，不是新的数值方案。UI应使用活动提供的参数，不能把数字烘焙进图标。当前上限有差异，属于既有产品差异，本轮不统一配平。

# 六 每条功能线的玩家操作流程

这些步骤用于可点击原型连接。每条都包含结果与回流，不能只画入口和一个按钮。步骤中的费用、时长、产出取当前报价；未提交前预览不能假装已经发生。

## F01 新玩家与老玩家进入

启动基地背景→检查连接与版本→有有效会话则恢复本人基地；无会话则登录／注册→新账号展示首机并命名→服务端保存后进入基地→显示当前服务器指引。老玩家直接恢复，不再强迫命名。会话失效回登录，注册结果不明先登录核对，不反复创建。

## F02 日常经营与收工

回基地→看离线摘要／当前目标→进入生产看可领量和容量→领取确认后更新真实库存→查看待修与已完工机体→完成一项现有日常可收工，也可继续出征。UTC日重置与离线计产上限按服务返回显示；摘要和日常达成不各送一次相同材料。

## F03 建设 供电与扩地

建设目录→选设施／道路／移动／供能工具→场景预览位置及影响→确认提交→显示真实费用／布局→回浏览模式。无效占地、邻路、超供电预算、超范围分别指出位置和原因；取消只撤草稿。锈轨首胜免费开东侧27格；工厂首次胜利再开南侧30格，当前布局保留，不画额外购买土地确认。

平台分支：点私人防御平台→选自己的兼容闲置武器／功能件→预览→安装确认→返回平台。拆件回仓要看容量，拆平台单独确认；不把平台绑定的零件同时列为机体可用件。

## F04 研究 配方与单件制造

生产／研究页→选现有研究项目→看供电、前置、费用与已掌握状态→确认研究→更新配方／生产效果→去部件制造→核费用及仓位→入库→机库安装。钻头累计亲自通关3次可掌握配方，首胜计入；提前研究与自然解锁并列解释，不暗示每次研究都赠一件钻头。

## F05 新造一台机器人

机库→设计新方案→选底盘和标准接口件→看3D、兼容与预算→保存到常用位置→按已保存版本制造→输入新机名、核材料／配方／容量→确认→新机进入机库并聚焦→可去本次编队。缺配方可有合法草案，但不能以“保存成功”冒作“制造完成”。

## F06 换装 底盘与战前行为

选已有机→点槽→选闲置实物→比较当前与预览→应用→确认后更新实装和仓库。套方案时逐槽说明沿用、拆出、装入、缺件；不同底盘先走独立换底盘报价，不偷换机器人身份。换底盘不兼容／超载时先解决部件；取消预览回原机。

行为分支在这台机体详情设置职责、护卫与交战偏好→保存／恢复推荐→回机库。改名、机身号与收藏分别保存，不被包装成收费强化。

## F07 战损维修 救援与机体回收

战报看受损及报价→修理站／机体详情→选择受损机→核材料与空工位→送修→显示在修和预计结束→到期核服务器→自动归队。满工位允许等待，无材料说明现有生产或救援条件；不添加未实现的排队预约或付费加速。

救援为符合条件的恢复途径，不是无限领资源；不符合时解释真实原因。机体回收先看返还、部件去向与不可再用后果，再二次确认；最后一台或忙碌机体不能回收。部分安装件会随机体封存，不能承诺拆光返仓。

## F08 锈轨单人与快速回收

出征→锈轨详情→选机、核12台／24点及费用→出发→认证进入→移动／集火／分支→到节点采集→打首领→到出口确认撤离→真实战报→回基地维修／换装。首领倒下不等于自动成功；正常首胜100%获得一件可装机实体钻头，已开的工坊自动出现同一实体，选件正常装机后原武器归仓。材料另记，首胜不直接掌握制造配方；仓满仍保留原待领入口。履带仍为现有底盘定义，不画成已实现的实体掉落。

已有首胜后，可在同关卡选择快速回收→看当天次数、普通能源、机体与仓容报价→确认→资源入库→回经营或手动出征。快速回收不启动战斗，不加真实通关、掉落或机体参战累计。

## F09 常规合作探索

出征合作入口→寻找队友，或建队／输入邀请码→队伍大厅→各人选自己的机体并看全队额度→各准备→队长确认全队出发→战场集结→全员到场即开，最多等30秒，届时到场者开战→本人指挥己机、队长标记建议→触发锈轨最终出口并结束全队本场→各人战报→原队再出发重新整备，或本次收工。

准备页换机、匹配等待、出发收费、战场集合必须是四种可读状态。锈轨出口由选中的合法存活机体至少一台靠近4米触发，并非要求全员机体到门；常规合作最终撤离结束全队本场，个人主动撤退才不终止队友。不要套用泵站各人独立撤离或秘宝全体本人存活机到门的规则。未到场、已离队或等待结算者需要明确说明；不能把好友慢加载画成已经战败，也不能由队长按钮直接完成队友风险确认。

## F10 工厂 武器库与泵站

工厂：锈轨首胜开东地→工厂卡→单人／双人好友→编队及费用→到场→车旁伴行、清障、过检查点→送达厂门→战果与南地解锁→回基地。没有采集按钮，情境动作围绕检修车和厂门。

武器库：南地开放→武器库卡→独行整备→正面清守卫或绕侧闸断电→回收武器箱→携箱到门确认撤离→首胜炮臂与实际材料→去装配；满仓待领。此关主动撤退放弃战利品，不能套用锈轨保留已采物资的说明。

泵站：世界／出征的当期事件→看时间、日收益与首通维修臂→单人或邀请码合作→各自编队和准备→窗口内出发→集结→清守卫、校准两阀→开共用箱→各自带己机到门撤离→个人回执→世界地图／基地。关窗阻新开，原场仍按自己的恢复规则处理；首通维修臂满仓时去机库待领。

## F11 本场结算与下一次整备

结束／撤离→“正在确认本场结果”→服务器回执→结果和结束原因→收益净变化→可展开本场机体击杀／施修／战损→维修、待领部件、回基地或允许的继续组队。不能先播“奖励已到账”再报结算失败。普通探索、营地归属结果、秘宝带货结果应有不同内容模板，而不是强塞同一张胜利表。

## F12 世界选址 攻占与驻防

世界地图→比较黄铜结构材料与线圈通用零件、时间和风险→登记当期资格→地点指挥台→选机并核本方含援军的额度与能源→实时进攻／合法接防→服务端判定胜负和归属→回该地点详情。

拥有后：驻军卡选择／炮臂架设→保存；采集站报价说明费用、产率／容量和失守后果→确认建造；有产出时看私人余位→领取真实可入库部分、其余原地保留→回地图。遇袭入口直达对应地点。失守后由页面自动更新权威归属，不能继续显示原营主的可领取／可建设状态。

## F13 好友 援助 参观与分享

按账号申请→对方同意→成为好友→可只读参观并返回。援军：受援者先满足地点资格→机主选待命机和协攻／协防→提议→对方接受后占用→开战时机主从记录入场指挥自己机体→结束或战后召回→原机归还及个人维修。战中解除好友或召回不能把已经参战的机器瞬间挪走。

分享：选方案和好友→发送→接收方看定义与本人缺件→存入自己方案栏→自行制造／实装。直接复制方案文本和好友分享是同一配置语义的不同来源，不另外送配方或部件。

## F14 秘宝争夺

选当期秘宝→先看自愿PvP和不可占领→单人或选一名好友→本人选机，双人分别提交→互看同一轮阵容与个人额度→各自确认风险→共同预留并候场→进同一战场→争抢／拾取→满包显式选替换物→回自己的撤离口→全部本人存活机体到位后确认→分别核带货、参与奖、稀有打捞与实际入库→回图／基地维修。

失能或超时丢临时货物，不永久丢机器人或原有部件。参与奖资格、当天次数和稀有机会／保底分别呈现：货物或参与奖仓满可能实际入库0；秘宝锅炉命中但部件仓满时不生成本次待领实物，当日打捞机会会消耗，保底留到后续合格开场日的有效带货撤离再打捞。不能套用锈轨首胜的待领按钮，也不能统一显示“奖励必得”。本人合法撤离不要求队友同时撤离。

## F15 私人袭击 防守回看与设施抢修

基地看到保护／预警→看强度、驻防机及固定底座→锁定前调整合法布局／平台，本轮预警尚未登记时可选一台合格待命机登记→来袭／自动防守结果→先看实际被掠夺与受损→按需展开细节或播放本场记录→机体送修；受损设施看免费恢复时刻，或核结构材料报价立即抢修→恢复供电／产线。已产出和身份的实际保护按服务器结果解释，不画永久毁号后果。

防守回看是已存在的可选能力，不是每次收工必看；公开营地当前没有同等回放入口，不一并承诺。

## F16 外观 方案栏与订单

进入商店→选外观／方案栏→外观可先在自己机体预览→确认当前模拟报价及上限→创建测试订单→内测模拟交易→查询同一订单直到发货→拥有后装备／方案栏容量更新→返回机库。测试人员控制成功、失败、退款的工具与玩家订单结果分开。真实支付接入前不设计成已经完成的渠道付款闭环。

## F17 账号支持与纪念展示

账号：设置→当前密码确认→生成／替换恢复码→一次展示并由本人保存；丢失访问时从登录页输入原账号、码和新密码→成功后重新登录。反馈只主动复制经过收敛的诊断摘要，不含密码／恢复码／登录凭证。

纪念：基地展示物→已结算战役→费用确认制作→收藏→免费换展→可另选公开刻名→回基地。它属于现有次级展示能力，不插入新手出征必经链。

# 七 每页都要设计的状态与返回

| 状态 | 玩家应该看见什么 | 能做什么／不能承诺什么 |
|---|---|---|
| 加载中 | 哪个内容正在同步；必要时保留上次画面并标旧状态 | 允许安全返回；不能用旧数据执行已失效操作 |
| 空内容 | 没机体收藏、没方案、没好友、无待领等具体原因 | 给现有下一步，不以空白或“错误”代替 |
| 前置未满足 | 缺哪次通关、配方、供电、资格、好友关系或时间 | 定位真实前置；不编基地等级／付费解锁 |
| 材料或容量不足 | 本次需要／拥有／差额；哪个仓已满 | 去现有生产、背包或调整方案；不跳不存在的购买战力页 |
| 机体不可用 | 受损、维修、驻军、援军、探索中、不完整或超载 | 指向该状态；不能用“点击解锁”误导付费 |
| 草稿／预览 | 与已保存／已装备清楚区分 | 可修改／取消；离开提示是否放弃草稿 |
| 提交处理中 | 清楚的动作和对象，锁重复提交 | 不因按钮动画结束就宣告成功，不靠不断重复点“购买／造机”恢复 |
| 结果待确认 | 请求可能已完成，正在核对原操作 | 保原身份／订单／意图；沿原key恢复核对，确认原收据后才清意图，不自动另造一笔；订单未知仍保原intent |
| 确定失败 | 人能理解的原因及下一步 | 保留可复用输入；不显示HTTP、UUID和堆栈作主要解释 |
| 成功 | 确认后的实际变化，定位新机／新件／新库存 | 一次反馈即可；不增加无意义领取或关闭确认 |
| 断线／被接管 | 最后画面变为非可指挥状态，提示原场接回或另一会话接管 | 已终局显示原结果；不误开新场或重复扣入场费 |
| 服务维护／版本不匹配 | 匹配版本或稍后恢复的说明及支持入口 | 不要求普通玩家查端口／重建容器；不许诺已有自动热更新 |

1084已按页面所有者实现自动读取、前后台门禁与真实异常恢复；基地未知保存自动核对原key后清意图，订单未知仍保原intent，不重发新订单。没有统一后台任务中心或任意写操作重试平台。页面P1–P5及真实钻头链、必要Android恢复切片组合签收，不代逐页手机全流程；F原false与末尾工坊native切页未运行保留。

## 7.1 时间 等待与后台

- 生产、维修、营地开放显示的是服务时间结果。倒计时归零由系统自动核权威状态，玩家不操作对钟或同步时间；不能靠本机时间自行开服、发产出或归还机体。

- 合作大厅准备、匹配搜索、战场30秒集结、秘宝等待对手分开设计。取消搜索、离队、撤退、撤离各有不同后果文案。

- PvE断线恢复、公开营地绝对截止、秘宝持续计时不能用一个“已暂停”覆盖。保留原场和个人结果接回，不把HOME操作当合法暂停手段。

- 系统返回键先关闭当前可关闭层；联机活动中的返回要说明是否只是离开页面，真正退出只能调用该模式现有动作。最终行为需按模式原型评审，不新增退出收益规则。

- 本轮没有通用系统推送、邮件或全局通知中心的实现依据。应用内预警与待办可以重组，不能画成已经支持离线推送。

# 八 战斗HUD与手机触控规范

## 8.1 HUD的信息优先级

1. 战场中央保留目标、敌我和路径，UI不遮出入口、箱子、阀门、护送车及关键战斗效果。

2. 上方显示本场目标进度、时间与连接状态；不要显示网络端口或每帧调试文字。

3. 拇指附近放己方选机／职责组和当前情境动作，战地维修显示剩余次数；探索系保留已有小地图与长距离移动。营地和秘宝没有同等现成小地图，本轮不以统一HUD名义新增。

4. 临时编组做轻量覆盖层；低频编组编辑不与高频集火抢同一按钮。队长标记与本人指令的视觉形状不同。

5. 撤退或放弃放在有清楚风险说明的位置，不能紧贴采集／确认撤离。秘宝使用自己的带货与撤离HUD，不出现假的维修按钮。

## 8.2 触控与适配

把当前下拉框改成能看见对象的卡片选择器：机体带名字／状态／点数，部件带接口／占用，活动带模式／风险／时间。只有音量等少量固定值适合简单分段选择，不能为换皮继续保留所有原生下拉。

Android官方建议触控目标至少48×48dp、目标间留约8dp；本项目把它作为有效热区起点，不把它误当48个Godot逻辑像素。当前工程基准960×540、canvas_items扩展只说明现状；UI团队可用1920×1080等工作画板，但交付须定义逻辑缩放、热区、安全区和不同横屏比例的重排。关键文字和按钮必须在实际小屏物理尺寸验证。[Android触控目标说明](https://support.google.com/accessibility/android/answer/7101858?hl=en)

覆盖16:9、常见长屏约20:9以及带刘海／圆角／手势边缘的横屏；基地与战斗保留中心可见区域，面板宽度和列表重排，不做整张图等比缩小。Android官方游戏适配文档也区分了安全可见区域与场景视野的处理，本项目采用保关键交互可见的原则，不照搬其中其他引擎实现。[Android游戏屏幕适配](https://developer.android.com/games/develop/multiplatform/letterboxing)

拖动列表不得误点按钮，面板上的点击不得穿透到战场下命令；建设拖动、镜头移动、机体点选需有模式／选中反馈。软件键盘出现时账号、密码、机名和确认按钮可见；密码隐藏，输入出错保留安全可复用内容。不能以缩小按钮解决内容放不下。

# 十 视觉与组件交付

## 10.1 视觉方向

采用可爱工业玩具：厚实轮廓、圆角机械面板、有限色块、清楚材质层级。黄铜、珐琅和铆钉可作为点缀，不把每个按钮做成密集管线。状态色同时配图标和短文字，敌方／危险、可领取、等待、受损不可只靠红绿区分。

机体卡优先大缩略图、名字、主武器与状态；装配用接口连线和兼容提示表达模块化。涂装不能掩盖实际职责和体型。字体、字号、调色板与皮肤尚未定稿，由UI团队给候选并在小屏检查；Blender场景规范不等于一套已确定的UI配色值。

## 10.2 组件最小集

交付按钮三级（主操作／次级／危险）、资源与容量条、机体／部件／方案／关卡／好友卡、接口槽与属性比较、预算条、进度／倒计时、状态标签、页签、列表／空态、情境提示、确认层、底部提示、加载与待确认层、编队勾选、临时货物栏，以及战斗选中／指令／队长标记反馈。每种都带可用、按下、禁用、处理中、错误、成功状态；这些是呈现组件，不要求开发先造新的全局框架。

正文、按钮、资源数值和错误提示分别给样式；中文长文本、长机名、三资源大数值、满仓、两行错误都要给样例。零件与机体缩略图优先复用现有资产库模型，不因此启动新增一批机器人或换美术体系。

先完成结构，再做皮肤。优先顺序表示设计顺序，不是删除低频现有功能。

| 交付轮次 | 必须产出 | 可核验的通过条件 |

| 第3轮 经营与公开玩法 | 建设／供电、研究／维修、防守、工厂／武器库／泵站、地图／营地／秘宝、好友援军、商店设置 | 个人／全队／每方规则明确；私人／公开／PvE风险不混；关闭、撤退和撤离不同；每个来源都有去向 |

设计文件建议用“P11 装配／默认、预览不兼容、部件不足、提交中、结果待确认”等命名；原型连线写对应F编号。每页标主要任务、数据字段、主次操作、出现条件、返回去向、正常／异常状态及关联入口证据。不要只交一组没有返回链和交互注释的漂亮截图。

需要设计评审确认的内容是视觉布局、信息密度、卡片／抽屉方案和具体文案，不再向研发要求临时发明新玩法。若设计提出统一各玩法额度、额外方案栏商品、自动领取、全局邮件、聊天、通行证、全战斗回放等，先进入候选池，不能默认算本轮漏做。

后续实现每个页面或公共组件都另建OpenSpec任务，先评审状态所有者、场景组合、输入／返回、请求提交及释放；本交接稿不授权把所有业务继续堆进基地脚本，也不要求把现有全部场景改成动态生成。
