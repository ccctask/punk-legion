# M15 好友组队探索

状态为开发自测完成，主代理独立验收记入 M15 的 OpenSpec 清单。房间与玩家档案维护代理共同负责本页。已验证 Godot 4.6.1、Windows 桌面、Android API 35 模拟器及本地 Linux 容器。

## 大厅读取与连接恢复

本节修订已通过源码/Godot Debug及1076签名安卓功能验收，现已进入当前试玩。首次读取前，准备、出发和复制邀请码等待有效队伍状态；临时断联保留名单与仍有效的选机草案，状态栏明确说明恢复情况。读取失败最多自动重试两次，仍失败则停止并提供手动刷新；登录过期停止请求，提示回基地重新登录。正常同步保持原有轮询及选机输入。[1076功能签收](../openspec/changes/archive/2026-11-12-m23-lobby-recovery-android/verification/root-r5-functional-review.md)

健康读取期间的准备操作只暂存一次。同一账号及队伍成功确认后才发送；读取失败、换队、隐藏或退出时不暗中提交，显示操作未发送。已发出的准备如果丢失回复，只读取权威队伍状态供玩家核对，不自动重发；独立业务拒绝不会被成功读取清掉。隐藏、暂停通知及战报遮罩停止普通读取，恢复先重新确认；未确认状态下可直接返回，不冒充服务端已经取消匹配。

实现、自测、主验和清理分别见[独立验收记录](../openspec/changes/archive/2026-11-11-m15-lobby-read-recovery/verification/root-review.md)。本轮两批各25个新账号、25场景/59检查；Android系统前后台及签名包整合另走M23，真实试玩版本仍查[安卓内测说明](android-private-beta.md)。

## 建队与出击

从 1040 签名内测版起，可从私人基地「日常 · 找队友 / 邀好友」或锈轨回收场「组队探索 · 寻找队友或邀请好友」进入大厅。没有邀请码时点「寻找队友」。第二名玩家开始搜索后，两人进入同一大厅，各自选机并准备，先等待的人任队长，也可以邀请第三人。等待或取消都免费，机体保持待命。搜索页每三秒续期一次，离开应用后超过十五秒自动停止；回来时已有队伍会显示其成员。点「取消寻找」若恰好已经配对，可从大厅点「离队」。使用邀请码的私人队伍和雾钟泵房各自组队。

签名内测 1009 在私人基地的首玩与日常中点「日常 · 好友组队」。Godot 桌面多窗口调试时运行 `docker compose up -d --build profile party`，从机库试车台进入档案、私人基地和锈轨回收场，点击「邀请好友 · 组队探索」。两至三位队员各用自己的账号。队长建队，其他队员输入八位邀请码。每人勾选自己已装配的待命机体，再点「准备」。全队上限为 12 台、24 指挥点。全员准备后队长点「全队出发」，每名队员按自己的档案扣去入场能源，冻结装配并登记任务。

1034 签名内测版会在队友准备状态刷新时保留正在点按的机体。如果该机体此时变为不可出战，系统会从待提交名单移除它。选机时，每台旁边显示按当前装配算出的指挥点。报价随勾选刷新，列出本人草案及与已准备队友合计的预计台数和点数。比如自己选 2 点基础机和 3 点目镜机，队友准备了 2 点机，显示本人 2 台 5 点、全队预计 3 台 7 点。查看报价和准备免费，每位成员出发时优先支付 1 能源；能源用完时可使用本人的救援凭证。若有人无法支付，整队本次出发不扣费，也不占用机体。

每人指挥自己的机体。第一处分支的守卫被击破后，至少两位仍参战的不同指挥官需要各自带机体到同一节点四米内并确认采集。巡查哨、线圈、首领与撤离沿用单人区域的战斗规则。队长在大厅离开后，由最早加入且仍在队伍的队员接任。战中主动撤退只停止本人的派遣，剩余队员可继续战斗。若仅剩一名有效队员，该队员可通过第一处协作门继续任务。

从签名内测 1019 起，战场右上角会按大厅中的指挥官名称显示每位成员：「在线」表示已通过房间认证，「待连接」表示初次进入或正在重连，撤退、过期则分别标明。已登记的机体即使出现在地图上，也可能仍在等待玩家连接。

从 1033 起，客户端在战场席位名单上标出当前队长。队长暂时掉线时保留标记权；若席位正式结束，按这场队伍的入队先后，由第一位仍有资格的队员接任。继任者可以立即在地图上标记移动位置或集火目标，队友自己决定如何指挥机体。原队长重新连入本场时也会看到继任者。战术标记的交接只在当前场次生效。

第一位玩家通过房间认证后开始集结。战场显示「已到场人数 / 总人数」和剩余秒数，全员到齐立即开战。到 30 秒时，仅在线队员出战，缺席者按个人过期结算。如果无人在线，房间直接结束。等待期间可以退出，机体不会行动，420 秒战斗时限从开战起计算。等待中断线重连沿用原截止时刻。

从 1033 起，房间会从集结人数中扣除主动退出者。例如三人报名，两人到场，其中一人点退出，剩下的人看到「1/2 人到场」。第三人连入就开战。暂时掉线的玩家仍保留到原定截止时间；主动退出者仍能在席位名单和自己的结算中查到退出记录。锈轨回收场与雾钟泵房采用相同的集结规则。

开发版的锈轨合作与泵站个人战报区分两种未出战结果。本人在集结期间点退出，会看到「集结时主动退出」。集结到期时未投入战斗，会看到「集结到期未出战」，包括曾连入、随后断线的席位。两种情况都保留出发时实际扣除的能源或救援凭证，机体不计参战场次。战后摘要与准备页的「查看上次个人战报」采用同一结果。已开战再撤退仍显示「主动撤退」。

开战后断线有 30 秒重连原席位。逾期退出的机组停止战斗，其他人的战斗继续。退出当时的战损和已采节点被冻结，整场结束后统一回写。胜利、撤退、战败及过期的奖励分别按个人结果兑现，已撤退机体不会分享之后获得的物资。一次任务持续最多 420 秒，未启动房间或房间长期停机时，领取凭据后 20 分钟的期限保证机体最终释放。

队伍大厅和战后回执显示本人的钻头制造配方进度。组队前已单人通关一次的队员，组队获胜后可看到 2/3；首次获胜的队友则看到 1/3 并领取自己的钻头部件。三次个人胜利免费掌握该配方。[配方与提前研究](solo-expedition.md)

## 房间和数据

本节适用于已通过联机复验的开发版；安卓 1007 的下一局仍需重新组队。开发版中，结算时可选择「本次收工」或「原队再出发」。签名内测 1018 支持队友先开下一局后，留在上一场战果页的人仍可点「本次收工」返回基地。收工暂时失败时，战果页会显示原因，可直接重试。上一场奖励和战史已入账，留队后一小时内可以换机、邀请队员和重新准备。保留原邀请码，每次出发生成新场次与逐人派遣号，队员只在整队再次出发时支付能源。离队与收工均不会再扣费。在机库维修后重新进入队伍面板也可查看上一场回执和续队入口。

准备名单按所选机体列出前排、火力、支援职责。战中队长选择「队长标记」后，点击地面或小地图建议移动，点击敌机建议集火。队友能看到六秒的文字提示和金色十字。两次标记之间至少相隔 2.5 秒，队员仍自行下令。

公开档案端口默认为 HTTP 24670。ENet 组队端口默认为 UDP 24569，开发环境可用 `PARTY_HOST_PORT` 调整宿主绑定，用 `PARTY_PORT` 指定桌面客户端连接的端口。Android 模拟器通过 `10.0.2.2` 到达宿主，两端都需能访问 UDP 和 HTTP。

- `/v1/party` 返回当前账号的可用机体、队伍与个人回执。建队、加入、准备、取消准备、离开与启动各走对应 POST 接口。准备摘要包含机体编号、实际部件实例与版本。出发前在一次事务里重新校验所有参与者，然后为每名玩家分别分配派遣与个人凭证。
- 服务端私有端点 `/internal/party/open` 核对个人票据，`/internal/party/settle` 接收全队终局。每名玩家的战绩、奖励和战损按其自己的机组结算，同一结果的重投返回已有回执。单人端口不能用于同一机体的组队任务。
- v18 为旧场次登记原队身份，保留历史队员与逐场收据。续队操作携带上一场标识，开战操作携带当前场标识。重试新一场报名时，服务端重新检查机体可用状态。
- 权威检查点和完成凭据在 `party-missions` 卷中按场次原子写入。档案只读挂载此卷，恢复时先查期限内的完成凭据，再查最近成员快照。备份档案时同时备份对应房间卷。
- 地图入口可实例化 `res://expedition/expedition.tscn`，添加到场景树前传入 `endpoint`、`token` 与 `start_in_party=true`，订阅 `closed` 返回原地图。组队与独行使用相同战场视图。

## 复验

`python services/profile/check_party.py` 使用独立临时数据库检查队伍预算、换件后重新准备、跨账号权限、队长移交、过期回执与幂等结算。Godot 命令 `--headless --path game --script res://party/tests/party_rules.gd` 核查每位玩家的指令序号、所有权、协作闸门、存档续战与分开结算。

单独设置 `PARTY_HOST_PORT` 和 `PROFILE_HOST_PORT`，再以独立 Compose 项目启动 `profile party`。运行 `python services/profile/check_live_party.py --godot <控制台路径> --profile http://127.0.0.1:<HTTP端口> --port <UDP端口> --size 2`，再将人数改为 3。每轮通过游戏界面的邀请、登录和准备启动真实战斗，核对重连和重登生涯。测试创建新账号，结束后只清理该测试项目。
通过 --video <MP4路径> 可录制各玩家真实窗口并排的完整对局，脚本记录每位玩家进队、采集开锁和各自战报。现有[双人实录](evidence/m15-party-2.mp4)（3分15.83秒、1280×360）与[三人实录](evidence/m15-party-3.mp4)（3分14.33秒、1920×360）已全片解码，均为6 fps。

## 首次合作日常

从私人基地的「首玩与日常」为初始机体命名。可用档案仓库制造维修臂，打开机库实装，在 AUX 功能槽装入这件实物；此时仍可选择好友组队。两位玩家输入邀请码、准备和出发，分别指挥自己的机体，在首个采集点共同确认并撤离。战后服务器按个人回执入账；返回私人基地可查看今日 1/1、实收和收据号。此时可结束当天游玩，战损检修可在本次继续或下次回来处理。

从仓库根目录运行 `python -B services/profile/check_first_coop.py --godot <Godot控制台程序> --output build/review-first-coop`。脚本起独立档案和组队容器、以两个新账号操作客户端；主视角从注册录像至自愿检修后回营。输出含可播放 MP4、正常客户端事件、独立回执与各阶段秒数。桌面、Docker、Godot 4.6.1 和 ffmpeg（或 imageio-ffmpeg）均需可用。单场即可完成日常，试玩耗时按实录报告。

### 首次试玩观察记录

首次内部邀请测试由观察者提供可启动的客户端和另一位已就绪的队友。试玩者只收到一句任务说明：“给自己的一台机器人取名字，和队友完成一次探索，回营后在你愿意的地方收工。”观察者不用替玩家点按钮。若必须提示，记录当时的屏幕、玩家原本以为会发生什么，以及给出的提示。

| 记录项 | 填写内容 |
| --- | --- |
| 版本与设备 | APK 版号、模拟器或手机、两人是否玩过本作 |
| 从登录到离开 | 注册、命名、换装、收到邀请、两席就绪、撤离、看到奖励、收工的分钟与秒 |
| 等待与求助 | 等队友、找入口、误触、重连分别花多久；不能独立完成时卡在哪一步 |
| 战后记忆 | 收工后请玩家说出主力机名字、这场承担的职责，以及一项能在服役累计中核对的贡献 |
| 玩家打算何时再玩 | 问玩家为什么选择现在收工或继续，再记录自愿维修、查看战史或接下一场花费的时间 |

按一次登入的实际耗时统计。分别报告首个可收工时点和玩家主动离开时点；若当场未完成，保留停留时长与原因。已有自动客户端录像可核对玩法和账本，定性体验由首次试玩者的观察记录补充。
