# PunkLegion 美术风格与横屏手游 UI 竞品研究（2026-11-21）

> 状态：**设计研究／待评审方案**，不是已批准的实现规格、已完成美术资产或实机验收。研究以游戏官方页面、公开截图、开发者/设计师分享为证据；**未声称对各游戏进行逐项实机操作**。本文件仅提出视觉方向和试验建议，不改写 PunkLegion 已冻结的玩法、数值、模型版本及业务规则。

## 0. 结论先行

推荐将 PunkLegion 的视觉语言定位为 **「温暖的玩具工业 × 可组装的机器人 × 轻冒险废土」**（Warm Toy-Industrial）。它应当首先是一款在**横屏手机**上清楚可玩的基地经营与机甲编队游戏，其次才是高装饰度的机械插画。

- **基地/建筑**：以 *Oddsparks* 的模块化、远距轮廓可读性为底，再引入 *SteamWorld Build* 的黄铜工坊和功能化工业细节。
- **机体**：借鉴 *Biped 2* 的友善体量、眼部情绪与简洁几何，再参考 *Lightyear Frontier* 的厚实工具机甲、功能分件；**保留本项目现有履带/双足底盘和标准接口**。
- **战斗可读性**：借鉴 *Botworld Adventure* 的小单位剪影、阵营/技能视觉分层；但不借用其部署机制、能力规则或商业化。
- **横屏 HUD**：借鉴 *Boom Beach* 的场景优先、边缘聚合操作；最重要的参考是 *SteamWorld Build* UI 设计师强调的“保持画面中央干净、少常驻菜单、视觉物理感与易用性平衡”。
- **直接行动**：优先做 P01 登录、P03 基地、P09 机库与 P11 装配四张 **同一套视觉语言** 的横屏真实比例原型；不要先大规模重做资产。

权威项目边界：[`docs/ui-design-handoff.md`](ui-design-handoff.md)（玩家任务、P01–P38、状态/返回规则）与 [`docs/playable-art.md`](playable-art.md)（冻结资产、Godot/Blender 组合与性能证据）。冲突时以权威文档和最新验收为准。

## 1. 调研范围、证据级别与比较方法

调研日期：2026-11-21。采用三个层级：

1. **官方/发行方介绍**：验证题材、系统及美术方向，例如官方商店、开发者站点和发行方站点。
2. **公开游戏截图/演示**：观察画面轮廓、材质、色彩、UI 占屏面积和场景密度。截图可能来自不同版本、不同平台，不等同于 PunkLegion 的手机体验。
3. **作者原始设计复盘**：特别采用 *SteamWorld Build* UI 艺术家 Sofie Wikström 的公开案例说明设计取舍。

评估维度：①基地场景；②机器人个体与组装；③工业视觉识别；④横屏小屏 UI；⑤与现有资产复用的可行性。下列评分为**本项目适配判断**，并非游戏客观评分或经过用户测试的数据。

| 游戏 | 优先研究部位 | 本项目相关度 | **可以学** | **不要照搬** |
|---|---|---|---|---|
| Oddsparks: An Automation Adventure | 模块建筑、路径、地面与场景层次 | 高 | 模块占地清晰、功能设备轮廓、柔和地表与机械反差 | 其自动化物流复杂度、满屏密集传送链 |
| SteamWorld Build | 黄铜工业城镇、建筑与 HUD | **极高** | 暖色世界＋冷色蓝图 UI、中心留白、设备具象化 | 过密桌面城建信息量、其专有图标轮廓 |
| Biped 2 | Q 版机器人、表情与动作 | 中高 | 大面轮廓、少量高辨识表情、关节玩具感 | 纯双足无武装结构、四人解谜的动作逻辑 |
| Lightyear Frontier | 工具机甲外壳、颜色与大环境 | 高 | 明快自然中厚实分件与维护感、色块分层 | 写实复杂纹理、大世界视距、农场玩法 |
| Botworld Adventure | 手游机器人与战斗信息 | 高 | 多角色剪影差异、色彩辨识、短时战斗反馈 | 自动部署/卡牌式能力、强化和货币机制 |
| Boom Beach | 横屏基地信息布局、触控路径 | 高（交互） | 场景居中、资源精简、主动作固定且可触达 | 海岛战争的造型主题、堆满红点与商业化入口 |

## 2. 六款游戏的具体观察

### 2.1 Oddsparks：模块建筑和可读的生产空间

- 从官网商店页与公开实际截图看，建筑常以一眼可认的上部功能件（切割、烟囱、工位、容器）区分，而不是仅靠文字名称。土地、道路、机器呈小体块组织，视角较高。
- 对 PunkLegion：冶炼设施、仓库、修理站、配电柱、军营机库应先过 **2 秒灰度剪影测试**：隐藏文字，仍能看出大部分职责。道路/电源状态优先使用地面标识与建筑局部状态，不新增复杂供电网络。
- 负面启示：当设施聚集时，小屏里地面和机器容易融为复杂纹样。规划空地与路面负空间比增加铆钉更重要。

参考：[官方 Steam 页面](https://store.steampowered.com/app/1817800/Oddsparks_An_Automation_Adventure/) · [发行方公开画面与资料](https://press.handy-games.com/oddsparks-an-automation-adventure-exits-early-access-on-may-27th)

### 2.2 SteamWorld Build：具象工业 UI 与中央留白

- 游戏的矿业/蒸汽机器人主题适合学习“**功能识别先于装饰密度**”：工坊、矿业和资源建筑以大件、夸张机械部件作为视觉符号。
- 关键一手案例：UI 艺术家 Sofie Wikström 表示，当初希望 UI 具有实物感，采用蓝图纸以对比橙色沙漠/棕色矿区；设计过程中发现过度工业化会破坏温暖感，于是进一步提高易用性、保持屏幕中间干净、少常驻菜单。这不是对设计者意图的推测。
- 对 PunkLegion：使用**深蓝石墨结构底＋柔和黄铜按钮＋浅蓝蓝图/选中态**，不要把厚钢板铺满 HUD；“金属感”只放在高权重边框、页签或大按钮上。

参考：[游戏官方页面](https://steamworldgames.com/steamworld-build/) · [UI 设计师公开项目复盘](https://sofiewikstrom.artstation.com/projects/oJ6gXm)

### 2.3 Biped 2：机器人不是一堆小零件

- 官方展示的机器人以简明躯干、头部表情和鲜明肢体动作建立亲和力。体块比例很容易在远镜头识别。
- 对 PunkLegion：现有 `PL_SteamCrawler`、`PL_SteamBiped` 保留实装接口，在外观包层面探索 **大头部可辨屏/光学窗＋2–3 个主色块＋可读武器外伸轮廓**。机身编号、挂点与武器不可被外观遮蔽。
- 注意：Biped 的简单造型不能直接等同于 PunkLegion 的模块化战斗机；要保留底盘、供能、武器和不同职责的可观察差异。

参考：[官方游戏站](https://biped2game.com/) · [Steam 页面](https://store.steampowered.com/app/2560240/Biped_2/)

### 2.4 Lightyear Frontier：重型机械与舒服的自然环境

- 官方产品资料确认机甲、建造、装饰与机械维护为核心；公开画面适合观察厚重分件、宽大的机械肩甲、工具接口、明亮天空与地表形成的氛围。
- 对 PunkLegion：强调“设备是可以拆修的”：关节连接、转轴、防撞角与装配槽保持几何合理性，**大零件决定形象，小磨损只用于强调旧物感**；不要给小屏机器满贴真实划痕。
- 性能不能照搬：此游戏以 PC/主机视角的世界尺度演出为主，其材质/环境密度不应成为 Android 性能承诺。

参考：[Steam 官方页面](https://store.steampowered.com/app/1677110/Lightyear_Frontier/) · [开发者谈创作方向的视频](https://www.youtube.com/watch?v=1xuWHKMDzy4)

### 2.5 Botworld Adventure：手机上的“认得清的机器人”

- 官方介绍支持多机器人收集与编队，公开战斗截图可见简化俯视场景、清楚的阵营/血条与战斗信息。机器人主要靠颜色、体型和攻击形态被识别。
- 对 PunkLegion：同屏多机时优先识别**本方/敌方、机体职责、当前选中、受损与行动状态**；将火力、维修、干扰的视觉反馈分开，避免所有技能都闪同色。
- 边界：PunkLegion 的实体部件、方案、拥有机器人和本次编队是不同对象；不能照搬 Botworld 的升级/抽卡或卡牌逻辑。

参考：[开发者官网](https://www.featherweightgames.com/botworld) · [Google Play 官方分发页面](https://play.google.com/store/apps/details?id=com.featherweightgames.fx) · [官方玩法演示](https://www.youtube.com/watch?v=Jet0zVFbXBE)

### 2.6 Boom Beach：横屏触控界面不是桌面启动器

- 官方产品侧重基地经营、资源、战斗/探查。可借鉴的是以基地为第一视觉层，资源与任务向边缘聚合，关键行为能够直接点按。
- 对 PunkLegion：不要采用最早概念稿那种占据横屏 35%–45% 面积的高耸钢板登录终端；尤其当安卓键盘弹出时，顶部 Logo 与中景要能优雅缩退。
- 仿照其信息组织，不复制专属按钮/建筑视觉和商业化干扰。

参考：[Supercell 官方页面](https://supercell.com/en/games/boombeach/) · [2026 年官方 UI 改动说明](https://supercell.com/en/games/boombeach/blog/blog/frontline-improvements)

## 3. PunkLegion 自有设计语言（建议稿）

### 3.1 原则

1. **可爱但有用途**：圆润外壳与微笑灯眼；炮口、关节、爪、维护装置按真实功能暴露。
2. **温暖而不脏乱**：黄铜与釉面主色；锈蚀只放在局部，不要全屏棕灰“脏滤镜”。
3. **镜头远近一致**：登录特写、机库中景、基地远景使用同一个机体比例与部件语言；高光不依赖局部高清细纹。
4. **显隐有序**：中间是可玩的基地/机体/战场；UI 主要贴边，打开详情时局部遮挡；降低常驻通知密度。
5. **状态比漂亮重要**：真实供电、已领/未领、修理中、占用、断线、提交未知等状态须明确可区分，不应成为纯装饰。

### 3.2 初始配色 Token（仅用于第一轮概念，待真机对比验证）

| Token | 建议 HEX | 用途 | 注意 |
|---|---|---|---|
| `ink.900` | `#243241` | HUD 底、深色机械壳 | 不宜大面积遮挡场景 |
| `ink.700` | `#37495A` | 面板/输入背景 | 须搭配明确边界 |
| `brass.500` | `#F3B645` | 主操作、友军工业黄 | 不用单色承载唯一状态 |
| `cream.100` | `#F7F1E5` | 主要文字/浅色釉面 | 优先可读性 |
| `cyan.400` | `#54CAD4` | 屏幕光、选中、辅助科技 | 避免全屏霓虹 |
| `mint.500` | `#78B7A0` | 维修/安全/正常 | 需配形状和文字 |
| `rust.500` | `#C97551` | 警告/锈蚀/敌方提示 | 战斗风险仍用明确文案 |
| `stone.500` | `#89918A` | 次要资源/设备 | 不与不可用态混淆 |

建议屏幕色彩比重：环境/地表为底，装备的 1–2 种主色最抢眼，高饱和状态色作为小面积标记。灰阶下保留轮廓与层级。建立正常、受损、维修、占用、断电、不可操作的多通道表达（文字＋图标＋轮廓）。

### 3.3 形体、材质与灯光

- **机器人**：主体由 3–5 个大体块构成；挂点、炮口、履带/足与维修臂独立清楚；近景才增添铆钉、小缝。眼部发光有限，避免整面泛白。
- **建筑**：每类设施一个醒目的轮廓锚点，例如修理站的大吊钩、冶炼炉的大烟囱、军营机库的半开卷帘与驻停机；屋顶视角也能区分。
- **材质**：优先复用当前顶点色/珐琅低面流水线；哑光主壳、略亮角件、少量发光屏、贴色警示纹。无须默认上高分辨率 PBR 贴图包。
- **灯光**：暖色主光、冷色屏幕/维修辅光，注意阴影范围；使用材质明度与色块替代大量动态光影层数。
- **场景**：可操作地面路径、选中轮廓和掉落物必须与地面纹样分离。禁止以场景地物遮住真实炮口、可点击建筑及退出/撤离引导。

## 4. 横屏手机四个关键页面提案

采用 16:9 为首轮设计基准，同时在更宽的 20:9 横屏与较低高度安卓机验证；**比例只是设计基准，不是强制拉伸或实际已验**。以 Godot 容器/锚点和安全区实现自适应。以下布局为提案，不改变文档中的业务定义。

| 页面 | 首屏组织 | 不应出现 |
|---|---|---|
| **P01 登录/恢复** | 背景使用真实基地视角；左/中展示基地与一台迎宾机器人；**右侧窄半透明任务卡**放账号、密码、登录/注册/找回；有效会话自动恢复。键盘弹出时卡片向可视区重排 | PC 风格巨大金属终端、必填服务器 IP、强制手动刷新、虚构邮箱/短信找回 |
| **P03 私人基地** | 中央完整基地；顶部单行资源；底部两端建设/出征主按钮、较小机库/好友；右侧情境待办可折叠 | 同时展开所有设施面板、完整技术日志、无差别红点 |
| **P09 机库** | 左侧可筛选机体卡，中央 3D 选中机与名称、右侧简短状态/装备信息；主动作进入装配/维修 | 用大下拉框代替机体、混淆实体机与方案 |
| **P11 装配** | 中央 3D 机体及可点击接口，左侧属性差异与合法性，右侧**自有闲置实体部件**卡；确认只提交明确操作 | 以保存方案冒充造机、缺件仍允许安装、换底盘默认免费 |

**P01 建议比例原型**：中心场景约占画面 60%–70%，登录卡建议从画面右侧约 28%–34% 宽度开始试验，实际按可读性与键盘遮挡测试调整。账号/密码真实文本框可聚焦；主操作触控目标初步以 ≥44–48 dp 作为检查值（不是当前项目的已验规范），不能因装饰铆钉缩小点击区。首次进入 P02 命名，老玩家直接回 P03，断网/过期会话显示**可行动的恢复提示**并保留安全输入。

**战斗/P19 延伸规则**：本方/敌方优先轮廓分组，目标与倒计时避开画面中部；点地移动、点敌集火、两个临时编组、战地维修都应有可操作的点按区域。联机菜单不宣称暂停。风险、已提交及未知结算反馈完全按项目权威状态。

## 5. 与当前 Blender / Godot 资产和工程的衔接

当前仓库明确采用 **Godot 4.6.1 + Blender 5.0**，并有冻结可编辑建模流水线。研究优先复用而不是替换：

- 已有 `PL_SteamCrawler r07-mobile-optimized`、`PL_SteamBiped r11-mobile-reviewed`、`PL_MeadowYard`、`PL_BrassWorkshop`、`PL_PuffSentry` 等资产；从这些机体与建筑开始验证“更明确的大形、颜色和光照”，不要擅自改变服务端绑定、枪口、槽位和动画。
- `docs/playable-art.md` 记载履带基础低面运行时默认双目/气炮约 **7,000 三角**、完整换装约 **8,564 三角**；这是**特定冻结资产的几何事实**，不是整场渲染开销或通用预算。不能因后期美术重设计忘记该基线。
- 已有三席短基线 P95 **34.13 / 41.18 ms**，没有达到 30 FPS 的 **33.333 ms** 帧时间目标；也没有可归因的前后 A/B。**不得写成安卓实际持续 30 FPS 已达标**。
- GUI 实现建议复用/收敛现有 Godot `Control`、`Container`、`Theme`、`NinePatchRect`、可伸缩矢量/贴图和真实运行时状态。机器人预览可按当前工程使用 3D 视口，不为静态概念图重建第二套机器人数据。
- 美术改动如需触及模块/状态/性能路径，先按 `AGENTS.md` 的架构评审、OpenSpec 和测试角色要求单独立项。**本研究没有修改代码，也没有提供新功能授权**。

### 5.1 可复用组件草案

| 组件 | 约束 | 验证 |
|---|---|---|
| 主按钮 | 文字＋图标、黄铜实体感；按下/禁用/处理中有状态 | 低高度横屏可触达、不可提交双击 |
| 次要按钮 | 薄轮廓/轻材质，不能压过主任务 | 与背景对比足够 |
| 资源条 | 结构材料、通用零件、能源和容量提示 | 数值增长/溢出/资源不足 |
| 机体卡 | 轮廓、名称、武器、职责、占用/维修 | 不通过颜色唯一表达 |
| 实体部件卡 | 接口类型、持有与占用、兼容/原因 | 与方案卡、机体卡视觉区分 |
| 方案卡 | 蓝图纸/版本感，与真实物件区分 | 保存≠制造、分享≠赠送 |
| 情境卡 | 有一个“下一步”主动作、真实状态 | 错误/连接恢复时不造假成功 |
| 风险确认 | 内容基于服务端实际规则 | 撤退/撤离/取消含义不混用 |

## 6. 工作量与验收顺序建议

**阶段 A：风格锁定（只做设计）**

1. 从现有冻结资产各截取同视角的履带机、双足机、修理站、装配工坊、基地全景。
2. 做两套候选：A“明亮玩具工业”（主选）、B“暖黄铜轻废土”（备选）；对**同一现有机体/建筑**换调色和灯光，不更换游戏身份。
3. 各出 P01/P03/P09/P11 四张真横屏图，同时缩到常见手机显示高度；进行 2 秒“识别功能/主按钮”检查与遮挡评审。
4. 用户确认视觉方向后，形成唯一 Token、组件表与可复用按钮/卡片/图标资源规范。

**阶段 B：一条最小垂直切片（需另行批准实现）**

1. 只选择 P01 登录＋P03 私人基地视觉更新；保留原业务功能、会话恢复和安卓键盘。
2. 先桌面 UI/布局检查，再 Android 键盘与真实触控，确认自动恢复/失败保留输入、断线语义、返回。
3. 再实现 P09/P11 卡片与选中反馈，验证真实库存、接口与预览状态，不改服务端。
4. 对比原版本和候选版本的同场景帧时间、绘制次数、显存与最低分辨率；达到目标再推进新场景美化。

**每个阶段的“通过”必须留存**：源图/源文件、所用冻结模型 ID、Godot 工程版本、目标设备/分辨率、字体可读性与触控记录、错误与恢复路径；性能必须有原始采样和相同条件对照。方案通过 ≠ 代码通过 ≠ 模拟器通过 ≠ 负责人真机终验通过。

## 7. 风险与明确不采用事项

1. **画风拼贴**：只复制艺术语言和信息组织原则，不复刻对方具体角色、图标、Logo、截图或贴图；研究截图只作外链，不直接引入游戏资产。
2. **PC 化登录页**：初版巨型右侧金属面板虽然视觉丰富，但明显减少了基地可见面积；先减重再谈精修。
3. **过度高模与特效**：现有性能尚存在明确缺口；不因概念稿好看增加多光源、高分辨率贴图和堆叠 Bloom。
4. **设计越过业务约束**：不得补画不存在的邮箱找回、抽卡、付费战力、战斗暂停、复杂兵种招募或新的资源生产体系。
5. **设计冒充实测**：上述 Touch dp、配色与区域宽度是候选值，必须经安卓真实小屏/输入法和既有场景性能验证。
