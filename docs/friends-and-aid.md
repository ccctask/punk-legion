# 好友关系与援军

适用于 M20 好友、参观、装配分享、支援派遣，以及 M19 房间对多人控制权的校验。状态为生效。维护角色为档案服务、营地房间与移动端负责人。已验证 Godot 4.6.1、档案 SQLite v14。

## 玩家入口

从玩家档案打开「好友与援军」，输入对方账号发送申请。接收人在自己的好友栏同意后，双方可参观对方基地、分享装配和提出援军派遣。参观复用实际私人基地场景，只显示好友公开的布局、建筑、道路和供能状态。移除关系后，重新打开的参观请求由服务端拒绝。

在「装配分享」选本人有效的工坊方案和好友。对方可预览定义版本、三个插槽及按当前空闲部件计算的新装缺件。保存使用接收者自己的方案栏，后续制造与换件仍走工坊。每台机体、每件实体零件和蓝图保留原账号归属。

## 派遣与指挥

受援者想进攻时，先在公开地图登记所选营地的当次入场资格。朋友在好友页选择本人一台待命机体，提出协攻或协防。待接收方同意后，机器人才进入援助占用状态。未接受的提议最多保留一天，已经接受的协攻只保留到该时窗的入场截止；协防机组由双方的驻防与召回决定。

受援方和全部援军共享每侧 12 台、24 点预算，固定炮塔也计入。协攻如已预选出战编队，系统用该编队校验；若未选择，至少为受援方保留一台实际可出的自有机体。正式开战时再次合并并校验所有实体。超过预算的那笔操作会整体撤回，其他机体状态保持原样。

战场启动后，援军主人从「入场指挥」接管自己的机组，双方能看到同阵营的其他机体。选择、移动、集火、维修与指挥序号按每位玩家分别校验，维修次数由所在阵营共用。战中离线的援军执行基础行为，可重连同场；攻防主人的撤退能力与援军权限分别判定。战前召回立即解除预留，战中召回或解除好友关系则标记战后归还。同场的唯一结算更新每台实际参战机体的服役累计并处理战损，由机体主人负责维修。

## 研发复测

### 好友协防机的维修费用

从签名内测 1059 起，派机前先核对目标营地与「协助驻防」。黄铜转运场和线圈港都适用。好友接受后，若该机实际进入守方阵容并在本场受损，胜负都可获得一次维修抵扣。机主在个人机况或基地修理站查看同一报价：原价 1 份结构材料、1 个通用零件，本次结构材料减免，确认后从机主私仓实扣 1 个通用零件。受援好友无需付款。

抵扣只用于该机的这次伤情。查看或提交失败仍可稍后送修，成功扣款后重复操作只取原回执。通过救援恢复或回收受损机体后，本次抵扣终止。协攻机与营主自有守军按普通规则维修。抵扣不会向任何一方仓库发放材料。

```powershell
python -B services/profile/check_friends.py
python -B services/profile/check_live_friends.py --godot <Godot控制台程序> --evidence <输出目录>
```

第一条命令使用临时账户与数据库覆盖关系同意、分享缺件、拒绝、预算和事务回滚、重复操作、战中解除关系、个人战损与收益隔离。第二条命令使用隔离的本地 Compose 服务，游戏内完成好友申请与参观、方案分享、协攻与三账号协防。成员重连前后都必须只能指挥自己的机体，两次战果归档至本人的机体档案。详见[营地房间与归属](camp-contest.md)。

派援军时选择黄铜转运场或线圈港，援助绑定该地点、进攻或驻防一侧及所选实体机体。两处均有争夺时，从援助记录进入其原场次。见[双地营地攻防](camp-contest.md)。
