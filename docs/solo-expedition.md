# M14 锈轨回收场与封闭工厂

状态为生效。维护角色为探索房间、档案服务与玩法验收代理。已验证 Godot 4.6.1 桌面客户端、Linux 容器与 SQLite 档案。

## 在游戏中游玩

1030 可从私人基地点「出击 · 锈轨回收场」进入独行准备页，点「邀请好友 · 组队探索」进入合作准备页。泵站从公开地图上的当期遗迹进入。[1030 试玩安装包与端口](android-private-beta.md#1030-本地内测)

1034 签名内测版在锈轨独行准备页列出每台机体当前装配的指挥点和全队合计。首次默认勾选前两台待命机体，可更改或清空。刷新保留可出征的选择；超过 12 台或 24 点时可以继续调整，回到预算内即可出发。已有场次可直接恢复。

1030 内测版中，锈轨独行、好友合作和泵站共用重连接口。探索断线时保留最后看到的战场，点「重连原场」，等服务器确认席位后就能继续指挥。其他窗口已完成同一次独行任务时，接回会显示该场个人战报。

历史版本 1035 中，在个人战报点「展开机体明细」，再点一台机体，可直接查看其本场时间线并翻页。同名机体以编号区分，点「返回机体明细」后可继续查看其他成员。实时战后界面和准备页的上次个人战报使用同一入口。

开发版在结算后自动显示个人战报。按机体编号查看生涯三项累计请进[指挥官档案](player-profile.md#m10-机体服役累计)。结算原因对应本人成功撤离、主动撤退、机体全部失能、达到时限或场次到期，未到场的席位单独标明。材料表列出实际入库、出征扣除和净变化，使用救援凭证时另列凭证。「展开机体明细」可查看出征时的名字、登记号、击杀和实际施修。战后维修报价在回基地送修时才支付。独行、锈轨合作和泵站分别保留本人最近的一份战报；收工后回到对应活动的准备页，点「查看上次个人战报」即可复看。[签名包两席核账](../openspec/changes/archive/2026-11-09-m23-personal-debrief-beta/verification/root-review.md)

Godot 桌面调试时，在项目根目录运行 `docker compose up -d --build profile expedition`，从机库试车台进入档案，登录后经私人基地出击。选择自己待命且完成装配的机体，最多 12 台、24 点。单场扣 1 能源，符合 M13 救援条件的账号可以核销一次救援券。档案 HTTP 默认本机 24670，单人 ENet 默认本机 UDP 24568；Android 调试时设备须能同时访问两个端口。USB 的 `adb reverse` 只转发 TCP，模拟器连 `10.0.2.2`，真机经局域网可用的 UDP 地址和对应端口接入。

节点、障碍与视野都在服务端。全队或点选单机后，可点地移动、点敌机集火、点小地图下达长距离移动；「前往目标」可自动寻路，采集必须在节点四米内。第一处分支在结构材料与能源间选择，分别有守卫。巡查哨有炮臂与维修车；线圈库守卫阻止未清场采集；最终熔炉首领带两台护卫。维修车每 3 秒向 8 米内相应重甲回补 4 点。炮臂可远程打击，钻头在近身对付维修车时保留全额伤害，厚甲对钻头取 0.43 倍。玩家可利用遮挡切断视线，可在全程使用两次战地维修。击败首领仍需到撤离点确认为胜利。这些数值属于样板配平。

胜利带回已采物资和一个实体部件，首胜额外结构材料并获得可实装钻头。仓满时保留首胜钻头领取权，在工坊腾出仓位后回到出击页领取。后续普通部件为炮臂，稀有部件为加固锅炉；未出稀有连续两胜后，下次胜利必给稀有件。普通奖品仓满折为额外材料，稀有奖品因满仓折算时保底不清零。撤退只保留已采物资；战败、超时或过期不发物资和部件。参战记录与损伤归原机体，返回档案后可恢复并在工坊实装。

首胜的钻头部件可以立即装上一台机体。要持续制造钻头，需掌握永久配方。锈轨单人和组队共用个人通关进度，每次本人胜利计一次，第三胜免费掌握。结算显示本次带回的实物和个人进度，组队时每人只看自己的回执。基地「生产与研究」也可查看进度，或在已供电的装配车间花费 2 份结构材料和 1 份通用零件提前研究。两条路线解锁同一配方，掌握后可在档案仓库用 5 份结构材料和 3 份通用零件制造一件钻头，再到机库把它装到已有机体的工具槽。

## 封闭工厂护送

本人首次通关锈轨并开放东地后，可从私人基地点「封闭工厂」。工厂常设。可独行（最多 12 台、24 指挥点），也可邀请一名已开放东地的好友（每人最多 6 台、12 点）。每人选择自己的待命机体并确认出发费用。全员到齐即可开战，集结最多等待 30 秒。

点「前往检修车」伴行。车旁缺少存活友机时，检修车停下等候；显示「轨道受阻」时，集火清除附近拦截机，再返回车旁。经过中段检查点后继续护送至厂门，全程限时 5 分钟。一人中途撤退，另一人仍可继续，双方按各自战果结算。

本人首次护送成功后，私人基地从 15×9 扩为 15×11，南侧新增 30 格，可接路、建厂并供电。成功护送按开场 UTC 日每天最多奖励 1 份结构材料，仓满时实际入库为 0，当日额度用尽。工厂回执、土地和日奖励独立于锈轨与泵站。[护送规则](../openspec/specs/factory-escort/spec.md) · [私人基地规则](../openspec/specs/private-base/spec.md)

本机联调使用 `docker compose up -d --build profile party`。整备与个人战果走档案服务的 `/v1/factory`，实战使用已有合作房间（默认 UDP 24569）。权威房间保存车位、伴行指令及每个席位的个人状态，重连可继续原场。

## 房间与持久化

- 档案 GET `/v1/expedition` 显示自己可选机体、当前任务、最近回执及保底。POST `/v1/expedition/start` 接收幂等业务号与所选真实机体编号，同一账号同时只能有一个单人任务。房间通过受信服务器接口核验入场凭据，其他账号及无票连接无法查询任务。
- Godot 在 `game/net/solo_mission.gd` 复用 M04 的 Simulation、A* 寻路、视线、武器射程和战地维修。每个任务单独实例化，客户端只发指令与单调序号。房间以 20 Hz 推进，约每 120 毫秒发送紧凑动态状态，场次、阶段和终局另走可靠同步。断线后可用同一账号重入；离线时暂停战斗，期限自入场起 20 分钟，实战上限 420 秒。
- 探索容器将服务器检查点与终局凭据原子写入独立命名卷。档案挂载同卷只读。离线清理先核实是否已有期限内的终局，档案停机越过期限也可恢复原胜利。没有此凭据的任务会按最近可信检查点结算过期战损。清理与重试共用同一回执并释放机体。备份恢复应一起保留档案与探索卷。
- 统计「开火时间」指任意参战单位最近 1.15 秒内实际开过火；「纯行军」为无交火且有己方单位移动。两者互斥。多带机体会提高遭遇耐久，4 台后停止缩放；更多合法机体、不同装备与熟练操作可缩短单场。详情与本轮实测见 OpenSpec M14 的 tasks。

## 复验

1. `python -B services/profile/check_expedition.py` 在临时库验证凭据隔离、结果拒绝／重投、过期、首胜满仓待领、第三胜保底与真实战损。
2. Godot `--headless --path game --script res://expedition/tests/mission_sim.gd` 对比不同编队、武器、交火／行军与超时；复用真实模拟器，以固定步长快速推进。
3. `python -B services/profile/check_expedition_restart.py --godot <Godot控制台路径>` 在独立容器开场后关闭客户端并重启权威容器；重连核对原进度和位置后撤退。
4. `python -B services/profile/check_live_expedition.py --godot <Godot控制台路径> --rounds 3 --outage --capture <PNG路径>` 冻结测试客户端副本、使用独立 Compose 项目及随机端口，从真实 UI 连玩三场；其间按实际服务端时间维修、使用回收实体换装再战。另一账号同时撤退。故障分支在第一场停档案，等房间真实胜利落盘后只修改隔离任务的到期时间至当次完成秒，再启动档案并核查唯一回执。参数省略时运行单场常速测试。
另有一场常速完整的[实测录像](evidence/m14-solo-expedition.mp4)。复验脚本可追加 `--video <MP4路径>`，按 6 fps 录制实际游戏窗口；编码使用系统 ffmpeg 或 Python imageio_ffmpeg 提供的 ffmpeg。

## 同账号私营闭环验收

在仓库根目录运行 `python services/profile/check_private_campaign.py --godot <Godot控制台程序> --output build/private-campaign-review`。脚本创建独立 Compose 工程，使用正常客户端控件注册、建造与移动设施、研究、领取、制造、出击、维修、换件和重登。需要有图形桌面、Docker、Godot 4.6.1 与 ffmpeg（或 imageio-ffmpeg）。五分钟自然生产、两场约三分钟的常速实战及工坊维修均计入运行时间。

主账号把结构库存使用到 2，待两座已供电冶炼厂实际生产后领取到至少 3，制造指定实体，并在两轮都选中它。首轮回收钻头，修理后实装并重登。逐次核对出战编队、两份任务回执及原机体参战累计。另一账号通过四次制造与实际入场用尽三种材料，在检修页申请救援、再申请一次观察冷却，随后用唯一凭证进入探索。

输出包含两段可独立播放的录像、建造和历史等截图与脱敏账本。对账程序以 SQLite 只读连接校验实际领取额、制造支出、两场机体身份、出战工具的实体 ID、维修时差与救援票消费。测试工程与生成的账户随临时容器卷一起清理。

## 锈轨外围快速回收（签名内测 1021）

取得锈轨回收场的首次个人胜利后，可在独行准备页选择一台完整待命机体执行外围回收。单人和组队胜利都可解锁。每个 UTC 日一次，每次花 1 普通能源，最多取得 2 结构材料。仓库只剩一格时先报价 1 份；仓库已满或能源不足时不能确认。领取回执后可马上使用该机体手动出征。

快速回收只记录库存变动。首胜奖励、钻头配方进度、稀有掉落进度和机体战报均来自真实战斗。真实首胜及安卓确认记录见[1021 验收](../openspec/changes/archive/2026-11-09-m23-quick-salvage-beta/verification/root-acceptance.md)。
