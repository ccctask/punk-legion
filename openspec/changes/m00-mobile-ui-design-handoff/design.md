# Design

## Context

本轮只做UI设计交接，动机与范围见proposal.md。当前签名1083和1082共享冻结客户端2345，1083仅改LAN端点；服务沿rc-1082-party-ack1。手机已进入私人基地，现有截图是现状证据，不代表全流程体验验收。

## Goals / Non-Goals

形成UI团队能直接据以画信息架构、线框和状态稿的文档。每个目标入口追溯当前可达入口及功能，标清建议、原型工具与未实现项；实际限制由对应业务模块拥有。不给UI团队夹带新功能、数值统一或技术重构。

## Decisions

### 文档落位与范围签收

root，2026-11-17签收。本轮是文档/设计审查，不是UI实现派单。M00拥有交接规范；各业务状态/费用/席位/权益的所有者仍见docs/module-boundaries.md，不新增运行状态、事务、依赖或场景。

| 资料 | 职责及理由 | 生命周期与所有者 |
|---|---|---|
| change/research/base-and-hangar.md | 代理只读核经营/机库真实入口、行号、动作和限制，保留技术证据 | 盘点代理写该文件；root审；不改源/资源 |
| change/research/expeditions-and-world.md | 代理只读核出征/世界/社交/战斗链路，避免依脚本名猜可达性 | 同上；工作源差异须单列 |
| docs/ui-design-handoff.md | 面向UI团队的权威交接主稿：入口映射、页面职责、全部功能线、状态及设计交付范围 | root整合签收；后续功能变更同步维护此入口 |
| 资料空间对应页面 | 可协作的交接正文，链接主稿/证据，避免复制无来源任务结论 | 进度代理按Pages技能发布并回读；root签收 |
| docs/README及任务卡 | 使研发、设计代理能找到当前稿与维护流程 | 进度代理维护最小索引 |

对照冻结源、可达组合和已有交付签收，分别标“现有功能”“目标交互建议”“工具/暂藏”“待定差异”。目录/静态控件存在不等于手机玩家可达；不把诊断Probe当玩家功能，不把下拉项目数当功能完成度。每条流程覆盖进入、准备、提交、等待/战斗、结果、回流以及异常；不能让关闭面板等同取消业务或联机暂停。

主要输出按玩家目标组织，技术路径放来源索引。跨入口同一功能指向同一目标页面，如基地建筑与机库快捷入口；不是复制两个功能或新建管理器。UI统一控件语言，保留各模式实际费用/限制/失败语义，不借设计统一数值。

## Risks / Trade-offs

- 当前菜单存在原型操作和支付模拟器 → 逐项列出目标去向/仅内部使用，不能抹掉当前现状或当正式支付。
- 各探索模式的兵力预算、人数和等待条件不同 → 按源逐模式展示，不根据策划愿景自行改规则。
- 只有局部已验收画面 → 表示“代码存在/已签场景”边界，不以新文档代整机触控测试。
- 页面较长 → 先放摘要、导航和屏幕清单，再列流程和状态，技术取证由附件承接。

## Review and delivery

以入口覆盖/流程闭环/当前与建议分离/来源及链接可追溯/范围不扩张验收。优先复用既有原图与证据，不启动模拟器、ADB、Godot或容器，不做数据迁移。外部交互参考使用官方资料并注明本项目采用范围，文档建议不冒已经实现。后续真正修改UI必须另开实现change并对场景组合、生命周期及依赖重新评审，本文不授予实现权限。
