# Proposal

## Why

当前正常泵房全场/满编P95为77.455/80.811ms，仍高于33.333ms；旧1010原生采样没有当前24机负载且Godot原生库缺符号。新核实的官方4.6.1 release符号包与当前APK的同构建原生库提供了可检验的归因路线，可先离线验证，不再盲试画质或修已停止的SF replay工具。

## What Changes

- 记录当前1077正式包/现有正常诊断包已profileable-shell及release native身份；先核官方符号SHA、x86_64 BuildID与已知函数地址，失败停在离线门。
- 符号门通过后，仅适配现有正常泵房入场/peer/清理编排，去掉SF启动依赖；优先复用已存在的1077正常诊断APK，不改游戏/模板/native库。
- 首次正常owner的a1已在prelaunch门拒绝，实际账号输入发生于Android/Godot启动图，未开战或record。只补首次表单可见的有界就绪门并保留原失败，不把设备安装完成当UI就绪，不靠增加固定sleep解决。
- 历史a3–a5的启动/IPC失败保原件；M01既有诊断a2已限定验证本轮实际端点/协议及返回，未修或定因间歇连接。a6手机首次实际同房6机/12点Ready，但同PID双GLThread标签使原唯一线程资格拒绝，仍未开场/record；不猜挑一个或在旧场补采。
- 改以锁定应用PID及进程starttime为用户态CPU采样对象，保全线程前后表与raw(pid,tid)样本分桶。唯一record使用--app及数值-p/--include-pid，保线程继承、仍30秒79Hz FP；按实际MMAP/同BuildID解析进程总计与线程桶，不从重复线程名推角色。
- 采样仅支持后续优化选择；保留全部失败/覆盖限制，不把CPU样本占比当呈现帧率、GPU根因或M06通过。
- a7原进程只读资格通过但导航固定坐标未选中本轮泵站，未开战/录制。将normal测试夹具限定到既有雾桥泵站，有限选择最近过去epoch并用实际服务事件核验；不改游戏时钟、位置算法、UIplan或产品规则，不在旧a7补录。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。沿用device-battle-baseline预算和原玩法；纯诊断工具与证据，skip_specs=true。

## Impact

M06/P0，当前1077+r2正式源/包/服务不动。开发代理交最小工具，test_lead独立离线及实际采集/清理，root仅规划/审原证据，进度代理维护原页。官方符号缓存约766MB下载且只解包目标ABI，实施前核空间/范围；无新引擎编译、渲染后端切换、采集平台或产品功能扩张。

1077仅作未变战中渲染链的CPU归因基线，不代G1–G3新源码整合后的性能验收。最终新候选仍须实际模拟器性能与玩家链证据；真机和声音终验依[负责人终验安排](../../../AGENTS.md#负责人终验安排)，在完整可玩版交付后由负责人执行。
