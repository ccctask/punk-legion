# Design

## Context

见proposal。已读docs/contested-treasure.md、现有contested-treasure规格及交付审计的M24剩余项。当前服务treasure.finish调用service_record.finish_mission并清除已结算席位私有events；treasure_combat生产assist等战斗事件。后续改动横跨写链、累计及客户端显示，必须按断言核依赖，不能仅比较一个文件或重跑早期整套恢复脚本。

## Goals / Non-Goals

形成当前交付的可复核M24范围，优先保护个人收益、既有部件、机体归还与三累计。此阶段不改变产品行为、预算、地图或部件数，不增加详细机体时间线；不将源码相同自动写成新执行，也不把历史依赖不同自动当产品缺陷。无AVD/服务运行授权随提案产生。

## Decisions

1. 先锁交付对象：rc1077完整源清单与r2已签实际源/镜像/配置分开；工作树只能用作对照，不冒充实际交付。当前APK、原r2四文件、health/operator稳定源锁不变。
2. test_lead从规格场景和具体旧主验取出断言，核原始日志/账目及相关调用者、事件生产者、事务边界和显示消费。优先对照1053助攻、1055累计、1056参与奖、1060稀有保底、1062/后续恢复与当前实际源；具体版本以真实来源确定，不凭编号判断。
3. 每个断言记录旧证据/依赖、当前生产依赖、变化的语义及是否影响结论。未变且原证据充分时继承；变动但已有后续独立原始主验时引用；剩余具体缺口才设计最小新库用例。未知保持未知，不为覆盖率数量翻修旧脚本。
4. 测试选集先静态检查入口及全部调用夹具。严禁含旧库恢复、旧格式升级或旧战报重投的整套入口；同版本本轮断线/重登/重复请求可在新数据验证。纯权威规则可用本机Python/真实HTTP，ENet和原生触控只有依赖变化确实涉及该边界才使用相应运行资源。
5. root审选集后单独确定运行源锁、预算与资源门。测试代理执行/清理并保存实际账目，root审原始证据签收；若需实现修订则委派原开发角色，不由root写功能或亲手测试。新运行如需特定状态，生成器明确记录其来源及构造前后，不能靠假设默认账号状态导致无效场次。
6. docs/testing维护当前证据和真实入口，docs/contested-treasure说明实际适用版本；旧审计快照保持原样。进度代理登记最小任务及是否仍有缺口，M06与真人/设备/渠道不随本项关闭。

## Risks / Trade-offs

- 写链相同但事件生产者变动 → 对照实际调用/事件生成与消费，不能只看累计SQL。
- 旧测试有迁移或失效命令 → 先读入口及依赖，必要时仅写新数据窄用例，不修整套历史工具。
- 将桌面/规则通过替代安卓或完整多人链 → 分开标注证据层和平台；只在实际依赖支撑范围签收。
- 审计无止境扩张 → 本项只处理M24当前交付差异，明确具体未证断言，主代理决定最小补验，不开25模块总回归。
