# Proposal

## Why

M00/M23需要把重复回归从主代理逐图操作转为专职测试代理的可选择自动化，并保留真实Android和联机边界。当前已有大量Godot/Python测试，但缺少统一入口、有效性登记及按改动复测规则；最近ADB启动、输入定位、关停和30秒集结编排失败造成了额外重跑。

## What Changes

- 生效协作规则明确：主代理负责范围、风险、方案和证据验收；专职测试代理负责测试设计、执行、资源收尾和测试文档；功能开发者负责实现与修复。
- 盘点并复用现有检查，优先评估固定GUT9.6.1与本机Godot4.6.1，GdUnit4兼容版本仅作比较；不升级引擎或并行引入两框架。
- 建立快速规则/场景测试、真实服务集成、Android边界三层目录和变更影响选集，记录证据复用/失效条件。取消主代理手工重跑同一完整矩阵的默认安排。
- 定义一个小型框架试点：真实生产规则、真实.tscn组合、异步失败恢复三类；须有负对照、报告及清理证明，并实测耗时后再推广。
- 当前1076保持待验，明确R3已取证场景与R4未完成的个人结算/冷启等缺口，不用框架绿灯替代玩家边界。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `engineering-baseline`：将分阶段联机验收的执行者明确为独立测试代理，主代理负责结果签收；增加分层回归、证据适用范围和测试文档维护要求。

## Impact

权威入口为AGENTS.md与docs/README.md，测试代理维护docs/testing/。规划及试点归本change，M23原任务仅同步角色与覆盖映射，不改游戏规则、已签1076包、服务数据格式或旧档。已完成调研、协作规则、文档及有界试点，交付本机按组快速回归入口；真实执行与主代理采纳见verification/root-review.md。不做全库测试搬运、覆盖率百分比工程或新CI平台。
