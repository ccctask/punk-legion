# Design

## Context

原1063计划从1062冻结两项修订发行；原安卓恢复失败保留在root-first-review。1064后继通过不等于当前1076相关入口仍通过。见successor-evidence-review的真实源变化/局部可复用矩阵；目标两条原有玩家要求保持。当前稳定r2交接已独立签，无需重启旧1063环境来收口。

## Goals / Non-Goals

只验当前两条玩家链及费用/安装/返还/战果单次性，不扩地图/商业化/新功能，不重跑全部经营、联机或六故障矩阵，不将M06/SF工具资格当本功能前置。纯文件审查不替代Android实际自动恢复UI。

## Decisions

1. **先准备后运行。** 顺序1.4→1.2→1.3；1.1仅历史发行事实。test_lead先交最小适用选集、工具/源锁、夹具生成与资源计划，root独立签准备才创建服务/设备。先核已有脚本入口/夹具，含迁移旧档路径的整套脚本不得执行。
2. **候选与复用。** 1076冻结515源f12829…ee42ae4及正式包066479…9b70为行为来源，实际隔离端点APK优先用父M06已签的现成派生包489e9a…b0ad（原有效payload仅cfg及索引差，debug签者10cdd8…ea927）。具体路径/实际SHA由准备记录再次核，不因文档名称假定可用。服务固定rc1076+c88f75…b82f有效源码；只读当前稳定Ops取版本/配置来源，不接管其数据或变更在线实例。现有SF回放包不用于该验收。
3. **新数据与最小服务。** 独立Compose项目/新卷/新号/新camp battle/新换装键；本轮正常API或明确可复现的新数据生成器构造营主/对手/部件，记录来源。不导旧库/回填/升级回退。优先只起profile+camp及必要共享auth/results卷；若当前契约实际需要更多依赖，先说明具体调用原因再由root扩预算，不能机械起六服。临时日程只作用于隔离新环境。
4. **两条真实行为。** 手机营主从正常基地发现真实对手攻击、从提示进入同一camp/battle、本人命令获权威接受、到终局与双方各一收据/占用释放。另在同一新号正常单件换装时仅截断一次已提交回包，观察手机自动用原键取得原收据及实装，不点手动重试/额外确认；RO核费用/物件安装返还单次。当前已实现恢复会自动重投同键POST，该传输重试允许且必须记实际次数；禁止生成新业务键、重复业务收据或重复扣费/返还，不能机械把第二次同键请求判失败。测试代理选择已验正常攻击端/故障代理并锁其当前适用性，不把服务写出当手机已恢复。
5. **有界与收尾。** 准备记录先给实际用例/时限/资源身份；目标至多一AVD+一必要攻击端、profile+camp最小服务及一个受控代理。设备工作开始前核宿主资源与实际keyguard，已解锁跳过输入，App启动一次并以当前游戏实际画面/状态就绪，不用SF ready文件。命令超时保首因与stdio、同句柄核已发生动作；有时限战斗自动衔接。保存证据后立即关闭自己的实例/代理/测试容器网络，保命名卷/镜像/AVD/证据；当前r2和共享服务不动。

## Risks / Trade-offs

- 当前入口变化使旧证据失效 → 只补矩阵中明确未覆盖的两个边界，复用未变局部及稳定运行交接。
- 异常代理把连接交付变成另一个问题 → 精确一条本人换装操作/一次回包中断，原键和账目关联，不丢所有请求或反复注入。
- Android环境未就绪 → 准备/实际产品失败分别记录，不据退出0、进程存在或原生日志无错推断玩家行为通过。
- 无源码产品改动 → 不为闭卡重签/发布新版；通过后核当前试玩仍可用及测试资源零残留，用原稳定交接证据说明当前配置未改。
