# Design

## Context

当前客户端索引与r2运行配置分开。历史health Compose默认指向早期游戏项目；health.py现有逻辑为30秒读取兼容接口及四类结果文件，7天保留，连续三次失败/超龄告警，最新样本超过90秒过期。见现行economy-and-operations规格。r2实际网络和结果卷必须从稳定台账及实际Docker身份核对，不能沿用默认名。

## Goals / Non-Goals

交付当前实例可查询的常驻健康采样，游戏数据只读，采样历史独立新建。只验证本能力；不重做监控实现、游戏功能矩阵、性能采样、账号/运维权限服务或迁移。root只审查，开发维护配置，test_lead操作资源并提交证据。

## Decisions

1. 稳定操作目录为`build/private-beta/operations/1077-health-r1/`，单独Compose项目`punk-private-beta-1077-health-r1`。锁定health.py副本及实际Python镜像ID，无build服务、无主机端口、根文件系统只读；仅独立history卷可写，四游戏结果卷只读，接已有r2网络。绑定脚本须拒绝缺失路径自动造目录。配置/说明不能依赖将归档change路径。
2. 开发先交配置/脚本SHA/维护说明及静态来源，不启动Docker、构建镜像或拉包。测试代理获具体运行放行后先查全机已有sampler、网络/卷/容器归属、可用内存及当前实际六ID；若已有正确实例，报告实际用途/所有者再由root确定接管或保持，不能先重复启动。缺失才用新history卷启动唯一采样器，镜像已有时直接锁定复用，缺失时记录一次明确镜像获取而非擅自换版本。
3. 行为规则优先复用可核原证据；若原源/夹具身份不足，仅执行已检查无迁移的check_health.py一次，独立新临时目录/DB，证明失败阈值、恢复、过期/保留与只读失败。不得让当前六服故障、停机或往真实队列注入假文件。当前服务集成仅做真实HTTP/四队列正常采样、容器/卷只读身份、report可查、有界同版本重启后本轮历史保留及新增样本。
4. 运行预算为零AVD/引擎/游戏服务/peer，一独立采样容器，最长5分钟观察及60秒收尾；只读轮询允许有界观察原容器，写动作不得超时盲重发。保存起始命令/容器ID/镜像ID/脚本及配置/真实卷网/样本/日志/资源终态。不得把SQLite样本自身正常等价于当前游戏功能或UDP健康。
5. 测试通过后root审原始证据并明确接管这一个常驻实例，稳定目录登记runtime/OPERATIONS及原六服/共享实例未被替换的证据；不改r2原四Ops。失败或未接管则按原配置精确down本项目，保新history卷/镜像/证据，确认未误删r2外部网络/四外部卷。临时测试worker/代理必清，不能遗留退出容器。
6. 当前交付手册/索引以新健康台账补充原六服维护入口；本项关闭“常驻健康采样缺配置”这一条，不关闭尚未验证的受限诊断/补偿和M06失败，也不把监控说成游戏弱网/帧率通过。

## Risks / Trade-offs

- 旧默认项目挂错卷/网 → 稳定配置显式指定，实际Mount/Network完整身份核对后采样；不猜活动目录或重建六服。
- 只读队列看到真实活场/在途文件 → 正常采样并如实告警，不清队列、不改mtime、不把异常隐藏成健康。
- 原健康规则证据源弱 → 一次独立新数据快速检查补证，不复制旧DB；正常重启读取本轮历史不是迁移。
- 常驻资源被误当临时垃圾 → root接管写用途/负责人/镜像/ID/卷网；本项若未签接管须清理并记录，默认不删卷。
