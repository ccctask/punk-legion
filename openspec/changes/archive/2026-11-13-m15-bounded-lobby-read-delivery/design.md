# Design

## Context

见proposal.md和已归档2026-11-13-m15-pump-lobby-read-diagnosis根签收。server.py当前SHA0691775779a393c24311f2b1490c48a1c45964703e7108461a76bb996dfe77b7，keep_connection已有6秒机制，对base/raid/workshop GET及少数成功POST启用。M09独立协议已有真实TCP新库夹具可选择复用，不能运行其写死历史输出/旧业务样例整套。M06无客户端插桩的1076端点包SHA489e9a82df585229cbf9ac08e7a201d05e59bbb748e07a36334833282432b0ad，已证明仅cfg/index变化，可直接复用profile33480。

## Goals / Non-Goals

恢复普通合作大厅读取的稳定交付，为M06整场验收移除入口障碍。生产仅改成功GET白名单；不改客户端、API正文、费用、编队、6秒值、请求重发或写路由。不在本change替换当前1076或做性能/战斗/全GUT矩阵。

## Decisions

1. 在既有GET路由tuple增加/v1/party、/v1/pump、/v1/factory，其余predicate/协议写回完全不变。三个入口共用父场景与同型状态读取；只修pump会让同一大厅流程留下无依据的差异。拒绝全量/v1 GET保活、延长超时/重试或改Godot线程，因为缺乏对应证据且扩大边界。
2. 开发代理交一行生产差异及必要不启动服务的predicate自测，停止编辑。test_lead独立加载当前实际server.py，在新库实际TCP验证三个成功GET完整定界/同连接连续读取/切换不同新账号、缺失或错误凭据401、显式close、HTTP1.0、重复或非零Content-Length、Transfer-Encoding、错误/未选路由和6秒闲置释放；保留正常与拒绝的socket/线程/监听终态。只覆盖新白名单及公共边界，不重跑旧制造/经济矩阵。
3. 实际Android用既有未插桩端点包，不编译、不签名、不加诊断header/logger。一个新Compose项目/六新卷/三新号，仅profile，通过已验原镜像只读bind本轮候选server.py，其余27源/协议5与rc1076一致。测试框架复用已签设备owner及精确down，保留当前1076/OGame/资产库。运行前root审候选SHA、工具锁/输入、白名单差异和包来源，分阶段放行。
4. 唯一原生场景：普通UI进入三席泵房，每席6机12点，手机选6/12后起算最多120秒。前30秒读初始3人；一位真实API陪测成员普通leave，手机须看到2人；约60秒该成员普通join/ready，手机须看到3人；约90秒手机UI点一次准备，须从后续权威状态确认本人准备与保留6/12（不出征）。用有界编排衔接成员变化，记录预定/实际UTC、关键PNG与SQL大厅状态，不让模型逐图等待延长窗口。至少初始/离开/归队/本人准备四个实际状态，普通健康读取不靠重复手动刷新。需要操作位置时按当轮实际PNG取坐标。无battle/ENet peer/SF，设备总≤20分钟。
5. 无插桩包没有逐HTTP事件，本轮只据实际UI/成员变化/账目确认相应玩家行为，不宣称每个自动GET均无丢包或给网络失败率。保留已有M06无日志失败及M15诊断作为历史baseline，不新造A/A2重复场次。原生结果不足/失败立即留证清理，不自动改范围或重复到绿。
6. 通过条件：独立协议边界完整，原生4个真实状态正确、无观察到的重试耗尽、选择保留、准备至多一笔正常UI提交、无mission/入场费/派遣；实际源码/包与保护及清理证据齐。root决定是否接受候选，无法说明效果则退回具体缺口，不以实现/自测通过交付。发行整合另行核源，不动当前试玩容器。

## Risks / Trade-offs

执行时序澄清：Ready计划点采用t0+105秒（取代上文约90秒），归队仍+60并立即留PNG；只在+105前有该PNG对应坐标与合法状态时正常点一次，总观察120秒不变。此安排给当轮识图留出时间，不允许等待模型延长总窗口或盲点。

该有限措施复用已接受的交付机制，不证明底层关闭/系统/引擎因果已彻底修复。更长的持有时间沿用原6秒上限与并发模型，不创建新线程策略。协议测试验证真实socket关闭而非仅头字段；实际Android结果是本轮有限观察，不保证所有网络情形。所有数据本轮新建，不迁移/重投历史战报。失败/超时路径及时关闭线程/监听/设备和精确删本轮容器网，保命名卷、原APK与证据。
