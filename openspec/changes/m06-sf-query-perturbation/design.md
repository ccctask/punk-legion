# Design

## Context

见proposal。执行边界以[已签唯一测量范围](../archive/2026-11-13-m06-pump-attribution-preflight/verification/next-measurement-scope.md)为依据。已查bench.gd具备本地Link和真实outing场景，probe.gd具备确定性当前规则生成结构；前者冻结process、后者headless手动动画，不可直接当原生动态入口。旧build.py还硬编码旧版本/路径，应只复用最小结构。

## Goals / Non-Goals

回答额外SF查询对固定动态渲染负载的影响，建立可审查的采集对照。此处不改玩法/画质/模型，不证明真实网络、全场30FPS或设备性能，不添加主循环/GPU/ETW平台。

## Decisions

1. **源与数据隔离。** 从锁定rc1076清单f12829a0cd3736b05eded3622172f7cce998510b911b2c6138e30f4ddee42ae4的515源复制到全新build/qa；诊断源仅增加qa入口/场景，修改副本main_scene、独立QA user目录和独立包名，移除副本私有端点配置。正式1076 SHA0664798785a8e5b76485ae213e428bc8205e281357fc4644cf07773ce5aa9b70保护。输出/改动白名单、引擎和模板/签名身份有锁，不混工作树或运行旧builder。engine显式传入并核console SHAbd9e27c6994a128aaab45cdda4d372de87b91900618ba2de55c6aa29248d5b56。debug key只核既有公开身份，不猜口令/生成key；准备失败保首因停止。

2. **当前新夹具。** 用当前PumpMission/Rules/Catalog生成三席各六台、每席合法预算/接口的内存编组，明确位置布局若为合成初始化，使用合法route。生成12秒确定性快照和活跃/死亡/开火时间线，所有区块使用同一新夹具。24是起始数量，允许自然死亡；不得导入旧raw/战报、禁动画/删轨道/改伤害或回填数据。画面阶段不再推进权威模拟，由本地Link按统一时间表驱动原场景正常_process，保留动画/音效/HUD/相机/画质。必须检查有真实交火并记录其覆盖，不把无交火过场当该负载。

3. **复位与时序。** 每块重新实例化场景、Link及其音效节点，清掉上一块状态，播放相同12秒片段：前2秒预热、后10秒统计。ABBA与BAAB共8块；用少量块级标记和同一设备单调时钟关联SF，不在窗内截图/查focus/逐帧写盘。预生成工作均在窗外。所有区块记录实际开始/结束、夹具标识/状态进度及重置证据，实际帧时间不靠虚拟30Hz模拟。若通过headless只能证明脚本路径，不证明Android画面。

4. **共同观测与额外查询。** 主观测共同每1.5秒，A加0.5秒查询/B不加；主统计只使用共同poll，额外原文独立保留，不能改变分母选择。启动前核实际Surface、缓冲行数/最大刷新率；60Hz/128历史仅是待核条件，不能直接套用120Hz。共同poll必须留余量、连续覆盖/重叠，实际间隔过限或数据缺失立即停止；不得跨poll造帧或删除慢帧。窗口边界与校时误差保守处理，实际每块完整覆盖且至少100间隔才比较。

5. **结论门槛。** 输出两序各自A/B分布、慢帧计数与query墙钟时间。B的P95在两序都改善至少10%才认为该负载值得采用较低扰动采集；方向反转/未达/覆盖不足则保留不确定或淘汰，禁止自动补轮。相邻帧非独立，不做显著性推断。共同观测本身、其他采集类型、普通联机和GPU原因仍未知，不能宣布M06通过。

6. **分工与资源门。** 开发只实现及最少必要自测；test_lead先独立准备：输入审查、一次诊断构建、脚本/fixture及源保护结果，root签准备后才启动唯一AVD对照。复用现有Windows Job/引擎/Android工具，不写另一套进程框架。引擎子进程/临时进程严格归属和超时，AVD持有不超过8分钟；零新服务/数据库/容器/陪测端，现有六服与共享服务不动。测试失败/超时也收尾；保留AVD镜像/文件，清理用完实例并提交终态。root不执行测试或操作设备。

root实施取舍：块前可用run-as写唯一触发文件，app在等待态读取、12秒播放期间不轮询；播完等待下一触发。窗外相同尾poll和一次logcat dump读取块标记，用唯一run ID/实际PID过滤，不能清共享全局logcat。设备monotonic日志用窗外uptime/log/uptime锚点关联SF，pad含包络/量化且不混host收日志时刻；实际证据不足仍拒绝。既有debug预检报告build/qa/m06-keytool-20261113-a1/report.json已签，公开cert SHA10cdd8cac007ad56a711e6c63f42e6782c3d4687f8491ce1a313a1e735bea927、store SHAd28d45a981f3fa5d81ab35091360d87750c8d8f5fa1005dff2a8af54f1e7ddae；文件相同可复用预检，不机械再列证书，最终签者仍核该debug身份。

## Risks / Trade-offs

实际开发解析检查补充：build/qa/m06-sf-dev-check-a1/check-result.json的首次import/check-only通过，但导入产生25个snapshot未含的生产脚本UID。root静态比较确认28新增为该25UID及3QA文件，既有源仅副本project.godot预期变化。允许将这25项的精确path/value/SHA与对应源SHA列为derived metadata锁，在正式prepare副本中预置；已有生产源/UID继续逐字节不变，禁止泛化容忍UID漂移或写回工程/冻结源。开发解析不重跑，正式prepare核预置后导入无新漂移。编辑器实际启动过ADB自动探测子进程，均在同一Job中结束；未执行设备操作，不报告ADB启动零。

- SF环形或时钟边界无法证明完整覆盖 → 停止并报告无效，不降低样本守卫求绿。
- 正常场景隐藏连接/回调 → 本地Link替换及空端点检查，准备阶段先核脚本/信号，无实际服务兜底。
- 不同顺序受宿主压力影响 → 固定同一片段和两序，只报告可重复门槛，不把顺序效应归因游戏。
- 新工具准备耗时超过可获信息 → 仅小型入口和必要边界检查；首次错误保留，由root评审一次相关修订，不扩为平台工程。
