# Design

## Context

动机见 proposal.md。已授权设备 3eb0ce6b，Android16/arm64，当前无游戏安装；手机192.168.31.106，电脑WLAN192.168.31.170。1082客户端快照 manifest2345b028c700bdfe66e449326941f18c28cc1795f13fa20c30d712513c13cbda；现行R2六服务与业务镜像已签收。发现记录位于 build/qa/physical-phone-install-discovery-2026-11-17-a2。

## Goals / Non-Goals

交付指定USB手机可启动、可连接现行服务的签名包。保持模拟器入口。不扩大玩法、框架、数据兼容或实体性能/声音终验。

## Decisions

### 实现落位与边界（主代理 root，2026-11-17 签收）

|入口|责任及放置理由|状态/生命周期所有者|

构建工具只依赖冻结配置和现有签名流程，不引入游戏对部署层的反向依赖。服务只增加发布绑定，不改变认证、玩法、协议和数据库。客户端既有M01加载策略保持不变，不增加运行时用户覆盖。

本轮具体补充签收（root，2026-11-17）：监督runner从已锁SHA的 inputs.builder.path 加载实际构建工具，替代冻结快照内旧工具；快照仅定义游戏源。既有审计器新增必填candidate-lock，root approval绑定其SHA，权威候选值为实际APK SHA/size、version_code、endpoint_host；payload审查显式接收版本/宿主，manifest2345及其他既有断言不削弱。历史1082输入与结果不覆盖。

### 部署与失败语义

在R2现有六服务上额外发布192.168.31.170的TCP33380及UDP33371/33372/33373/33374/33376，容器目标沿现有配置。先验证解析后仍保留127.0.0.1，服务/卷/镜像/env未意外变化，再核活动和重建。使用本轮现行同版本数据，不导入任何旧库、不删除卷。未知操作结果先观察同一实例，不重复写入。失败保存证据并恢复已记录的同版本配置；不得宣称安装成功。

防火墙先检查，只有实际需要才新增限手机192.168.31.106到WLAN192.168.31.170上述端口的具名规则；不关闭防火墙、不改Mihomo/TUN或路由。权限不足报告事实。

USB仅对序列号3eb0ce6b安装已审定包，不卸载、不清数据。授权阶段后由一个有归属ADB会话完成安装/启动，结束清自身daemon。不得读取无关个人数据。OEM若真实弹出安装确认由用户点击。

## Risks / Trade-offs

- WLAN IP变化使固化地址失效 → 交接明确同WiFi/电脑服务运行及地址限制。
- Docker多IP发布可能不受当前环境支持 → 必须解析配置并以实际LAN访问验证；不擅自放宽到全网卡。
- 需要短暂重建服务 → 先核活动，记录完整身份与配置，保留现行卷；不重复完整玩法测试矩阵。
- 包构建工具与冻结快照内同名脚本不同 → 分别记录实际工具SHA及冻结游戏源SHA。

## Acceptance

核1083实际签名/包名/arm64/端点及冻结游戏源；确认默认模拟器配置仍可生成。实际服务新CID/双绑定/健康及手机HTTP、必要UDP握手证据。USB安装、前台启动及正常入口到服务的可见结果。未执行的实体性能和听感标为负责人终验。临时进程清理，保留六服务及必要LAN规则用途清楚。测试不通过返回具体缺口。
